# Apple HEVC HLS qualification

The session/device-information profile remains the initial baseline; it is not a live report of the optional per-playback HEVC request. Direct playback uses the existing Apple profile. A separate, process-local calibration may qualify HEVC HLS transcoding after that original negotiation has already selected transcoding. Pending, unavailable, software, slow or invalid calibration keeps AVC. One failed HEVC playback receives a separate AVC recovery; later track changes keep AVC for that viewing.

The bundled `App/Resources/hevc-main8-1080p30.mp4` is an original synthetic reference generated from FFmpeg's `testsrc2`, with no third-party footage, audio, network source or account data. Its SHA-256 is `49c05630450bf2f3b6ed25e8e377bdd0a1ab669e1e862f3361cbaa8856d4bb8e`, size 616822 bytes. It contains 60 HEVC Main 8-bit 4:2:0 frames, level_idc 120 (level 4, main tier), 1920×1080, 30/1 fps, two seconds, limited-range BT.709 SDR. Regenerate in a scratch directory with:

```sh
nice -n 15 ffmpeg -hide_banner -nostdin -y -f lavfi -i testsrc2=size=1920x1080:rate=30 -frames:v 60 -an -c:v libx265 -preset fast -crf 36 -threads 1 -filter_threads 1 -pix_fmt yuv420p -profile:v main -level:v 4.0 -x265-params pools=1:frame-threads=1:wpp=0:bframes=0:info=0:colorprim=bt709:transfer=bt709:colormatrix=bt709 -color_primaries bt709 -color_trc bt709 -colorspace bt709 -color_range tv -tag:v hvc1 -map_metadata -1 -movflags +faststart hevc-main8-1080p30.mp4
```

Encoder version changes can change the bytes. A replacement needs a new reviewed hash and an actual metadata/frame-count receipt. The runtime checks its pinned bytes, actual Core Media format/hvcC, colors, every source PTS/duration, every decoded output's pixel format/dimensions/PTS, hardware selection, drops, errors and elapsed decode time. Hardware-required VideoToolbox decoding must deliver all 60 distinct frames in more than zero and at most two seconds. The provider publishes only the tested Main/level-4/1080p30 tuple, then applies the same portable `prefersHevcTranscode` eligibility predicate against the foreground screen's actual current-mode pixels and refresh capability. Larger displays conservatively keep AVC.

This short synthetic decode is a conservative calibration point, not proof of all HEVC Main streams, a maximum decoder level, or sustained thermal performance. The timer includes compressed reading and decode, but not asset loading, hashing or session creation. It cannot preempt a blocked system decode call; all probe work runs away from the main actor and playback never waits for a pending probe. Results last for the process only; an unavailable or busy initial probe does not retry repeatedly.

The second PlaybackInfo request disables Direct and stream copying and constrains HEVC output to Main 8-bit, level ≤4, ≤1920×1080, ≤30 fps, SDR, HLS/fMP4. The selected URL must carry these constraints; actual GET flags also disable auto/video/audio stream copying. An unsupported or ambiguous selection falls back to the original AVC decision before opening any HEVC URL. These request bounds do not inspect the remote encoder's output bitstream. Native HLS acceptance and actual output conformance on the supported server remain integration evidence.

Apple documents hardware-required allocation and the hardware-selection property in [VTDecompressionProperties](https://developer.apple.com/documentation/videotoolbox/kvtvideodecoderspecification_requirehardwareacceleratedvideodecoder) (iOS/tvOS 17+), and synchronous output when both decode flags are clear in [VTDecompressionSessionDecodeFrame](https://developer.apple.com/documentation/videotoolbox/vtdecompressionsessiondecodeframe(_:samplebuffer:flags:framerefcon:infoflagsout:)). Jellyfin's [StreamInfo](https://github.com/jellyfin/jellyfin/blob/master/MediaBrowser.Model/Dlna/StreamInfo.cs) serializes codec-qualified output conditions into the negotiated URL. No Jellyfin implementation code is included here.

Sanitized OSLog notices use subsystem `app.pictureshow`: category `HEVCQualification` records `Reference measurement=pending/measured/unavailable` and `Capability measurement=... eligible=...` with actual display mode pixels/refresh when available. Unavailable measurements carry `reason=unknown`, not an inferred hardware failure. Category `Playback` keeps the viewing/session identifiers on its `Negotiated` notice and adds `hevcHLS`, `boundedHEVC`, and a fixed-vocabulary `container`. These distinguish pending/unavailable qualification from eligible capability followed by AVC selection; no URL, token, raw error or server-supplied container string is added.
