# Apple feature parity

This checklist covers **all 92 feature IDs** in the Android reference manifest: **65 Implemented**, **27 Platform-dependent**, **0 Gap**. It is a source and acceptance inventory for the Apple follow-up, not a claim of complete release acceptance. The reference is [the shared feature contract](../spec/features/README.md), including the main-branch recovery semantics and additive phone/tablet behavior.

- **Implemented** means a production path exists and the row identifies its source plus a specific test or observable check. It does not mean every acceptance clause has passed on every Apple device. The last column records known limits and missing verification explicitly.
- **Platform-dependent** means an Apple capability boundary or intentional native substitute is identified. It does not convert an unavailable feature into a passed test. Native AVKit transport, Apple captions and platform services may differ while preserving supported outcomes.
- **Gap** means a concrete reference behavior is absent or incomplete, beyond a justified native presentation difference. Runtime-pending by itself is recorded as missing evidence, rather than silently scored as a pass.

Verification references below are executable source locations. **A referenced test method or vector is not a claim that the latest runtime run passed.** The integration owner appends actual simulator destinations, commands/counts, screenshot review and failures after the pilots. Core HTTP/vector checks prove logic and wire contracts; they cannot prove focus, spoken VoiceOver, decoder output, native Siri Remote touch input, or hardware resources.

[SV] is the strict recursive JSON adapter for the checkout's [shared vectors](../spec/vectors/README.md), including catalog, negotiation, reports, recovery and settings/application. Its default input is this repository's spec directory, with `PICTURESHOW_SPEC_DIR` retained as an override. Unknown fixture operations/families fail. [Core tests] and [Core client tests] provide additional named regressions; [Media tests] verify direct server URL construction, credentials and origin/header requirements after removal of the loopback relay. [UI] contains live simulator acceptance cases, including `testLiveVerticalSlice`, `testServerHLSAndResume`, `testSeriesSeasonsEpisodeAndTrackControls`, `testAccountSearchSettingsAboutAndLicenses`, `testiPadLandscapeAccountAndCatalogNavigation`, `testNativeTVDirectPlaybackMenusInfoAndRemoteScrub`, `testNativeTVManualNextStartsAdjacentEpisodeSource`, `testQuickConnectCodeAndCancel` and isolated direct-startup trials.

The player uses `AVPlayerViewController` on both platforms. TV has full-bleed video, native transport/clickpad scrubbing/info panels, server Audio/Subtitles in `transportBarCustomMenuItems`, and skip/next in `contextualActions`. iOS retains native AVKit controls with supplemental sheets. Exact Android raw key-repeat thresholds and control chrome are not Apple requirements. The [README](README.md) documents direct viewer-`ApiKey` media URLs and their log/diagnostic exposure, unsupported custom-header sources, AirPlay reachability, caption limits and remaining real-hardware checks.
