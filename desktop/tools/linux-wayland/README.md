# Compose + EGL Wayland diagnostic

This original MPL-2.0 adapter owns an xdg-toplevel video surface with a separate
SDR wl_subsurface above it. Compose `ImageComposeScene` renders controls and
performs pointer hit testing. Only changing UI pixels go through wl_shm; decoded
video remains on the native EGL/GL path. This is a diagnostic surface, with no
Jellyfin session or production desktop accessibility/window integration claim.

The HDR mode requires wp_color_manager_v1 to advertise parametric descriptions,
ST2084 PQ and BT.2020. It waits for a ready image description, attaches it to the
video surface, and presents mpv output targeting PQ/BT.2020 through a 10-bit EGL
window buffer. The compositor may map that HDR surface to an SDR output. Protocol
acceptance does not establish connected HDR output, gamut, luminance or calibrated
color correctness. The UI surface retains the compositor's default SDR encoding.

Build with `build.sh MPV_PREFIX WESTON_SOURCE OUTPUT_DIRECTORY`. Generate protocol
bindings from installed wayland-protocols and a Weston source tree. Run the desktop
`wayland MEDIA EVIDENCE [--sustain=125] [--sdr]` mode with `SPIKE_WAYLAND_BRIDGE`
pointing to the built library. Public inputs must be generated CC0 fixtures.
The probe requires the Weston test-seat and capture protocols for automated
input and screenshots; those diagnostic extensions belong only in an isolated
test compositor. They are unnecessary for ordinary video/UI presentation.

The prototype currently selects `/dev/dri/renderD128` for direct VAAPI EGL import.
Device discovery, keyboard/IME/accessibility, interactive resizing, robust errors,
multiple monitors and distribution remain product integration work. A dedicated
render thread owns EGL and all mpv render calls. Updates drive rendering, target
time blocking is disabled, EGL swap interval is 1, and swap completion is reported
to mpv. The `SPIKE_WAYLAND_LEGACY_PACING` diagnostic switch restores fixed 60 Hz
polling with mpv target-time blocking for a controlled scheduling comparison.
Screenshots are isolated compositor captures and never part of the video path.

## Reproducing the isolated compositor

The measured compositor source is the official Weston16.0.0 tag archive:
`https://gitlab.freedesktop.org/wayland/weston/-/archive/16.0.0/weston-16.0.0.tar.gz`
(SHA256 `6a81af51045ccb2813f3a1d63ff8a66c121743c1a5ff3ce78388660bf650c55c`).
The measured Mesa was26.0.8 and wayland-client1.24.0. Weston is a diagnostic tool,
not a bundled playback dependency. With its development dependencies installed:

```sh
meson setup build --prefix=YOUR_WESTON_PREFIX \
 -Dbackend-drm=false -Dbackend-headless=true -Dbackend-pipewire=false \
 -Dbackend-rdp=false -Dbackend-vnc=false -Dbackend-wayland=false -Dbackend-x11=false \
 -Dbackend-default=headless -Drenderer-vulkan=false -Dxwayland=false -Dsystemd=false \
 -Dshell-lua=false -Dshell-desktop=true -Dshell-ivi=false -Dshell-kiosk=false \
 -Dcolor-management-lcms=true -Ddemo-clients=false -Dsimple-clients=[] \
 -Dtools=info,debug -Dtests=true -Ddoc=false
ninja -C build -j2
ninja -C build install
```

`run-isolated.sh` starts a finite1920x1080@60Hz headless compositor with color
management, its test-seat module and a capture-authority module. It stops that
compositor by PID on exit. The test plugin needs null guards when used outside
Weston's own test runner; `patch-test-plugin.py` applies those guards. These
modules allow broad capture/input in that isolated compositor, so do not load
them in a normal desktop session. They never enable host permissions or change
household services. The probe sends an actual `wl_pointer.button` event from
the compositor test seat into the application's subsurface, and Compose performs
the hit test. It does not call the button's handler as a substitute for input.

The fixtures can be generated by `desktop/tools/fixtures.py` and
`desktop/tools/performance_fixture.py`. Keep fixtures and private machine paths
out of public evidence. Record the native library, application JAR and fixture
hashes with each run, and reduce compositor captures to JPEG800px/quality50 for
visual review. None of these receipts establishes physical HDR scan-out.
