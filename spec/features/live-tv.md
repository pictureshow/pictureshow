# Live TV and DVR (launch draft)

**Status (2026-11-10): Android reference implementation present; device, integration and platform qualification remain separate gates.** Server configured by its administrator; Pictureshow consumes it as a client. Sources: [Jellyfin setup](https://jellyfin.org/docs/general/server/live-tv/setup-guide/) documents M3U/HDHomeRun tuners and XMLTV/Schedules Direct guides; [Plex DVR](https://support.plex.tv/articles/225877347-live-tv-dvr/) documents tuner/antenna recording intent with a Plex Pass requirement. Pictureshow does not require that Plex entitlement, provide their channels or configure a household tuner silently. Exact operations are in [launch API](launch-api.md).

## Executable reference rules (2026-11-10)

The Android reference uses `core/livetv/LiveTvClient`, `LiveRules` and the existing playback owner. These source paths and the checked-in vectors establish implementation, not device acceptance. Apple, web and desktop must translate the rules and execute the vectors; their UI and playback qualification remain separate work.

- Guide windows are positive, at most 24 hours, with exact half-open UTC overlap (`end > windowStart && start < windowEnd`). Offsets are parsed as instants, so repeated local hours retain distinct program identities. Invalid/reversed timestamps and programs from channels outside the current authorized channel set are omitted. Pages deduplicate by program ID; overlapping broadcasts are retained as server facts and gaps remain empty.
- Natural channel sorting compares numeric components without floating-point conversion or fixed-width integer overflow; numberless channels follow numbered channels, with name then ID as deterministic ties. Filtering and scrolling never tune.
- An account key and request generation own each guide cache. A late response cannot update another generation/account. Last-loaded metadata may remain readable offline, but tune/recording actions require connectivity, no pending refresh, a fetch within five minutes and an airing that has not ended. A fresh program/channel/policy read still precedes viewer mutations; a cache is not an entitlement.
- Recording defaults arrive as `SeriesTimerInfoDto`. One-off creation projects common timer fields, including `ServiceName`, `ExternalProgramId`, padding, priority and `KeepUntil`, while dropping the defaults' ID and series-only options. Series creation retains unrecognized provider defaults. Existing schedule edits carry explicit dirty fields, refetch the timer/rule, apply only supported dirty fields to fresh server data, then read back saved values. An accepted request whose values are ignored is not called saved.
- Every favorite, timer, rule and recorded-file mutation rechecks the current viewer's policy. Absence is not permission, and there is no administrator token fallback. Timer cancellation and recorded-file deletion use different resources. Delete a recorded file with the normal `DELETE /Items/{id}` content operation, after fresh per-item/content permission checks; `DELETE /LiveTv/Recordings/{id}` can only unlist metadata and is not file deletion. Read back both the recording and normal item; a remaining item or failed verification is not success. One-occurrence cancellation uses `/LiveTv/Timers/{id}`; cancel-series uses `/LiveTv/SeriesTimers/{id}` and retains completed recordings.
- Create writes are serialized and journaled before transport. A failed or cancelled response may mean the server accepted the request. Before another create, refetch and reconcile exact program/channel/start/end scope. Exactly one matching schedule acknowledges the request without another POST; an unresolved journal entry or multiple matches prevents a blind resubmit. A confirmed refusal can be corrected and retried. Invalid local edits, including an empty day selection, show a readable validation error and retain the form; they do not submit or terminate the screen. The Android journal checks synchronous persistence success before transport and survives process death; clearing an unresolved request is an explicit recovery decision, never an automatic timeout retry.
- Status labels distinguish all seven server values and preserve unknown status text. Conflict status does not promise tuner availability or completed recording. Completion is based on recorded media/player evidence, never a guide end time.
- Live playback opens a required source once using a bound JSON `OpenLiveStreamDto`, including the device profile/caps and open token. The returned source/live ID is authoritative. Owned Stop carries `LiveStreamId`; explicit Close follows, accepting only 404 as already closed. Sources which were not owned are not closed by another viewing.
- Cast uses the negotiated live classification rather than guide duration, and live loads omit an explicit start seek so the receiver chooses its live edge. Private sender ownership survives detach/process death; failed Close retains its temporary credential for an explicit cleanup retry. Receiver range/codec behavior still requires separate device qualification.
- The live timeline comes from the player's measured live window/default position and window offset. A paused position that falls outside the moving buffer remains paused and shows Buffer expired until explicit Go live/Play. Scheduled broadcast duration never supplies a seek range or completion signal.

## Vectors and proof

Finished recordings open the normal media-detail route on Android TV and touch. The download control uses the shared offline implementation. Growing recordings (Type Recording or IsInProgress true), explicit non-Completed recorder states, infinite sources and per-item denial cannot be downloaded; omitted recorder Status is valid for ordinary library episodes. Item facts and viewer policy are re-read before each transfer attempt. The integrated Android device flow still needs a permitted completed recording saved through the app and played locally with the server unreachable. A successful server download or a recording shown in the list does not prove that Android flow. Compact guide cells bound visual text without discarding the full program title and dates used by the reader and detail view; `live-guide.compact-cell-retains-full-program-metadata` checks retained metadata, and native UI checks cover cell bounds and the three-line rendered text budget while retaining the full reader label. TV activation tests use remote key input and retain the no-tune-on-focus assertion; actual D-pad and screen-reader behavior are separate device checks.

`live-guide.json` (guide overlap, boundaries, denied channels, duplicate pages, DST folds, natural sorting, tune eligibility and cache ownership/freshness), `live-dvr.json` (defaults projection, dirty edits, unsupported fields, statuses and real-client mutation traces) and `live-source.json` (player window/edge/expiry policy) are executable Android reference suites. `LiveRulesTest` and `LiveTvClientTest` additionally exercise wire query bounds, viewer policy changes, mutation/readback and process-independent pending-write journals. Other platform runners have not yet been ported to these suites; adding JSON alone does not establish parity.

Further compatibility and device coverage: `guide-window`: UTC bounds, overlap, gap, DST folds, timezone change, channel sorting, stale paged response; `live-source`: RequiresOpening/AutoOpen, failed open/close, JSON/query field consistency, Stopped auto-close then Close-404, expired paused range, rapid tune generation, shared live ID ownership, infinite duration, sliding ranges; `dvr-write`: timer defaults projection, one-off/series preservation, permissions, ambiguous create readback and duplicate suppression; `dvr-status`: all conflict/status enums, rule versus occurrence cancellation, recording deletion, growing→complete.

The isolated demo 12.0.0 fixture uses two generated CC0 continuous channels, generated XMLTV and a one-stream tuner limit. Its API acquisition, scheduled recording execution and independently decoded completed file have been observed. Android TV and phone emulators have rendered the live source and completed recording and exercised one-off/series creation, cancellation, recording removal, Pause/Go live, offline cached descriptions and reader paths. Each device receipt must name its APK version; server API evidence alone does not establish an Android interaction.

Natural buffer expiry, growing-file replacement during playback, commercial-marker media, vendor/Fire hardware and the supported-server-version matrix remain separate qualification. The fixture's stream limit does not establish conflict enforcement: display actual server conflict status and do not promise capacity. Finished-recording download needs the integrated downloads subsystem. Other platform UIs and vector runners remain ports to perform. A household server is never the target for tuner configuration or this fixture.

Deletion qualification: the demo Live TV DELETE returned item404/list absence while leaving its generated TS file. That receipt proves unlisting only. The standard content endpoint was independently verified as an ordinary viewer to remove a fresh generated TS file as well as both catalog entries. Client deletion receipts still need to identify their API and device version; API404 alone is not proof of freed disk space.

## Native presentation contract (2026-11-10 layout review)

LIVE-01/02/03/PD03 use components by role: native selected-state tab rows, one focusable channel list item, a shared guide ruler, catalog recording cards and grouped schedule rows. The TV header fits approximately the first quarter of a 960×540 viewport; touch content follows its app bar, tabs and compact filter row. Focus never tunes. Request attached initial content focus after load and restore the exact channel/program/recording/schedule key on Back. TalkBack cursor evidence is separate from app focus evidence.

A TV guide fixes the channel column while one horizontal position owns every timeline row and the single sticky ruler. Half-hour ticks and program cells use the same fractional time mapping: the reference three-hour/1080dp canvas places ticks at 0,180,…1080dp. Gaps stay empty, overlaps retain separate lanes, and an accent line marks the current instant only inside the displayed window. TV minimum lanes are60dp and grow with text scaling; focused-program title/time/episode/overview appears above the grid. A visual cell narrower than72dp omits text but retains its complete accessible label and program details. A Grid/List switch makes the linear alternative available to everyone. Day selection plus Earlier/Now/Later replaces machine timestamp input. Each platform can adapt dimensions while keeping the mapping and information intact.

All Live TV timestamps share the device's 12/24-hour preference and locale. Ordinary clocks omit timezone offsets; repeated DST local hours retain offsets to distinguish their instants. Same-day ranges omit the repeated date and repeated AM/PM period only when both periods match; cross-period ranges keep both. Tomorrow/weekday labels appear when a date is not today. `live-presentation.json` fixes representative en-US/New York clock, fold, range, ruler and narrow-cell cases; localized native equivalents must retain meaning.

Program detail uses artwork, title, channel/time/episode metadata, overview and one action group. Watch is available only while airing; a future program shows its start time. An existing timer is identified explicitly and cancellation opens its scoped schedule; scheduled cells show a recording dot. Recording cards retain normal detail/resume/watched controls and status; file deletion belongs in contextual actions, separately from timer cancellation. Schedule options use named selections (new/all, this/any channel, minute padding, latest-count retention, named deletion policy), preserve unsupported provider fields, and keep priority in More options. Review/confirm remains explicit and does not reset failed edits.

The guide's red recording dot requires a nonblank occurrence TimerId. A SeriesTimerId alone describes a rule and
does not establish that its filters schedule this particular airing. The accessible program label includes the
scheduled state when the occurrence exists; visual color is never the only indicator.


Round 2 native density contract: at the standard TV 960×540 viewport, the focused-program preview replaces the generic title header,
and native tabs share a line with the horizontally scrollable guide filters/day strip. The fixed 200dp channel column and one pinned
28dp ruler leave space for at least six complete 56dp channel lanes at font scale 1.0. Lanes and the preview grow with accessibility
font scale; extra channels scroll vertically rather than shrinking text. Touch keeps 60dp minimum lanes and a 72dp fixed channel column.
