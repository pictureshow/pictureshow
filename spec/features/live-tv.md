# Live TV and DVR (launch draft)

**Status: required launch scope, not implemented/verified here.** Server configured by its administrator; Pictureshow consumes it as a client. Sources: [Jellyfin setup](https://jellyfin.org/docs/general/server/live-tv/setup-guide/) documents M3U/HDHomeRun tuners and XMLTV/Schedules Direct guides; [Plex DVR](https://support.plex.tv/articles/225877347-live-tv-dvr/) documents tuner/antenna recording intent with a Plex Pass requirement. Pictureshow does not require that Plex entitlement, provide their channels or configure a household tuner silently. Exact operations are in [launch API](launch-api.md).

| ID | Behavior | Acceptance criteria |
|---|---|---|
| LIVE-01 | Live TV destination offers Channels, Guide, Recordings and Schedules according to server/viewer capabilities. | Distinguish no tuner, no guide, permission denied and network failure. Channel tuning remains possible without guide data. No commercial IPTV/guide account is assumed. Settings link/explanation tells a server admin what is missing without requiring every viewer to be admin. |
| LIVE-02 | Channel list shows name/number/logo, now/next and favorites with paging/search. | Sort channel numbers naturally with stable fallback; unknown program says No guide data. Favorite mutation respects user data permissions and refreshes authoritative state. Playback starts only on activation, not focus/scroll. Blocked channels never leak their program metadata through cached guides. |
| LIVE-03 | Guide is a bounded channel/time grid with Now, date/time selection and accessible program details. | Fetch overlapping windows (program end after window start and start before window end), deduplicate paged programs, render gaps/overlaps without inventing broadcasts. Store UTC instants, display local timezone including DST repeated/missing hours. D-pad moves channel/time predictably, retains selected program/scroll on Back; screen reader has a linear channel/program alternative. At large text every action remains reachable. |
| LIVE-04 | Tune using PlaybackInfo and returned live source, not a guessed file URL. | Open required source once; handle busy/no-source/denial and last-selection-wins. Populate OpenLiveStreamDto JSON consistently, without conflicting duplicate query fields; 84A records honored fields. On Stop include LiveStreamId in stopped report; server can auto-close. Explicit owned Close afterward treats 404 as already closed, other failures remain cleanup failures. Release only owned encoding/live resources on change/error. Initial tune retains PLAY-02 preparing/Back semantics. |
| LIVE-05 | Live timeline distinguishes live edge, observed seekable window and unavailable time shift. | Seek/pause within observed ranges only; Go live seeks actual edge, never scheduled program duration. If paused position expires, retain paused state and explain Buffer expired; explicit Go live/Play seeks edge and resumes. No silent auto-resume or arbitrary rewind/start-over promise. |
| LIVE-06 | Program detail offers Tune now, Record once or Record series according to program and rights. | Future programs cannot Tune; current programs can. One-off form shows channel/time/padding/priority from defaults. Series additionally shows new-only, any-time/channel, days and retention if supplied by server/provider; absent fields are disabled with reason and existing values preserved. Confirm exact scope, read back timer/rule, reconcile timeout before duplicate create. |
| LIVE-07 | Schedules list one-off timers and series rules with status, channel, time and recording policy. | Edit padding/priority; series adds days/time/channel/new-only/keep limits supported by provider. Preserve unedited defaults/unknown fields. Cancel one occurrence differs from cancel series; confirmation starts on Cancel and explains retained completed recordings. Server failure leaves the original schedule readable and Retry actionable. |
| LIVE-08 | Conflicts and errors are reported from server status. | Show New/InProgress/Completed/Cancelled/ConflictedOk/ConflictedNotOk/Error distinctly with known reason. Overlap warning can be labeled an estimate but not authoritative tuner capacity prediction. Offer edit priority/time/cancel or admin guidance; refetch after changes. No unsupported automatic conflict resolution or guaranteed recording claim. |
| LIVE-09 | Recordings show recording/in-progress/completed/failed availability and play through normal negotiation. | A finished recording supports resume, tracks, watched state, download and casting when permitted. Growing recording has only actual seekable range; deletion/replacement during playback is recoverable. Cancel an active timer and delete its recorded file are separate actions with exact scope. |
| LIVE-10 | Recording deletion and schedule writes honor server rights. | Read uses EnableLiveTvAccess; management uses EnableLiveTvManagement; deletion follows content policy/server response. Read-only viewer can watch permitted media without enabled scheduling/deletion controls. A permission change or removed channel invalidates caches and explains denial; no silent admin-token fallback. |
| LIVE-11 | Guide freshness and schedules survive network/lifecycle changes. | Keep last loaded guide labeled with fetch time/offline status; expired cached programs are not silently actionable as fresh. Reconnect refetches before a timer mutation. Backgrounding client does not cancel server-side recording. Account switch cannot reuse another viewer's channels/schedules. |
| LIVE-12 | Recording commercials/markers and completion remain honest. | Only server-supplied valid media segments drive existing skip behavior; no client claims Plex commercial detection or skips live ads on a schedule guess. Live stream stop is not VOD completion. Recording physical end is measured independently of guide duration. |

## Platform-dependent rows

| ID | Platform-dependent limit | Acceptance and fallback |
|---|---|---|
| LIVE-PD01 | Live seek/pause/start-over depends on returned source and each player’s real seekable ranges. | Unknown/nonseekable stream offers Live and Stop/Tune only; no fabricated DVR rewind. Test Android/Fire vendor decode and Apple growing-HLS range changes independently. |
| LIVE-PD02 | Web HLS/MSE, server auth, trusted origin and CORS differ by browser. | Unsupported live format uses a negotiated compatible stream or clear unsupported reason. Browser suspension follows playback-mode policy; no closed-tab recording control promise. |
| LIVE-PD03 | TV guide grid and touch layouts use different navigation/geometry. | Same channel/time/program/record actions, linear reader alternative and exact Back selection restore; no missing schedule management on TV. Server owns tuner/storage, so no local device tuner is required. |


All native platforms use their existing video engine/profile with live HLS/direct-stream support measured on that engine. Web needs native HLS or hls.js/MSE with working CORS/auth and a trusted media origin. No platform needs local tuner hardware: Jellyfin server owns the tuner and DVR storage. Guide grid may be a touch list or TV grid, but channel/time/program/detail/schedule actions and reader alternatives stay equivalent. Real TV remote channel-repeat cadence, Fire codecs, Apple live ranges and browser tab suspension require their own acceptance.

## Planned vectors and proof

`guide-window`: UTC bounds, overlap, gap, DST folds, timezone change, channel sorting, stale paged response; `live-source`: RequiresOpening/AutoOpen, failed open/close, JSON/query field consistency, Stopped auto-close then Close-404, expired paused range, rapid tune generation, shared live ID ownership, infinite duration, sliding ranges; `dvr-write`: timer defaults projection, one-off/series preservation, permissions, ambiguous create readback and duplicate suppression; `dvr-status`: all conflict/status enums, rule versus occurrence cancellation, recording deletion, growing→complete.

Configure an isolated M3U tuner with two legally generated continuous channels, an XMLTV guide with controlled near-future programs and a one-stream limit. Prove guide→tune→record once→completed file→resume/download on isolated 10.10.7, 10.11.11 and 12.4; household 12.0.0 remains unchanged acceptance server. Exercise overlapping recordings, guide gaps, read-only viewer, UTC/DST and cleanup. Server APIs alone do not prove tuner acquisition, scheduled execution or a decodable recording.
