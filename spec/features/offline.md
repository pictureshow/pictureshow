# Downloads and offline (launch draft)

**Status: required launch scope, not implemented or verified here.** Apply [shared rules](shared.md), [queue/ownership rules](session-control.md) and [exact API/version boundaries](launch-api.md). Sources inspected 2026-11-03: [Plex Downloads](https://support.plex.tv/articles/downloads-overview/) describes permission-controlled personal-media downloads and original/lower quality on supported apps; [Jellyfin Android download behavior](https://github.com/jellyfin/jellyfin-android/tree/master/app/src/main/java/org/jellyfin/mobile/downloads) is behavioral evidence only. No GPL implementation is incorporated.

| ID | Behavior | Acceptance criteria |
|---|---|---|
| OFF-01 | On native platforms supporting durable offline, download movie/episode/album/track/playlist or selected season episodes for travel, with scope, quality and storage preview. | Check viewer download/playback permissions and actual item access. Expand a container into a stable paged snapshot, deduplicating stored media while preserving queue order. Show count and known size or explicit estimate. Do not offer finite download of live/infinite streams. Web follows OFF-13; tvOS follows OFF-PD03. |
| OFF-02 | Download quality is Original, Compatible video (up to 720p/4 Mbps or 1080p/8 Mbps), or Compatible audio (128/256 kbps), subject to proven server/output support. | Download is not streaming negotiation alone. Original requires local codec/track support or an explicit warning before transfer. A finite, independently playable converted asset must pass offline checks before a compatible preset is enabled. No usable conversion means an honest unavailable preset plus supported original; conversion remains a launch qualification blocker for convertible fixtures. No server-side offline job/DRM is invented. |
| OFF-03 | Native download states are queued, waiting for Wi-Fi/storage, preparing, transferring, verifying, ready, paused, failed, missing and deleting. | Pass requires all OFF-03a through OFF-03e, reported individually. |
| OFF-03a | Ready is atomic. | Only complete verified media, required resources, metadata and manifest become Ready in one durable commit; kill before commit cannot expose a partial asset as Ready. |
| OFF-03b | Progress does not invent totals. | Show percent only with a known total; unknown length shows received bytes and indeterminate status. |
| OFF-03c | Pause, resume and cancel survive lifecycle changes. | Restore paused/incomplete jobs after process death. Cancel/delete removes owned partials and ignores late successful callbacks. |
| OFF-03d | HTTP resume validates the source. | Append only on matching validator plus 206 Content-Range at the expected offset. A 200, changed validator, invalid range or truncated body restarts or fails without corrupting Ready assets. |
| OFF-03e | Jobs respect reservations. | No concurrent attempt writes bytes beyond its reservation or the global budget; reservation failure becomes Waiting for storage. |
| OFF-04 | Native Downloads screen opens without a reachable server and groups ready/active/failed media, with Retry, Pause, Delete and storage settings. | Airplane-mode cold start opens a cached account's downloads before online token validation. Cache title/art/episode/track labels and available track choices. Uncached full-library browsing is not implied; unavailable items explain why without infinite spinner. Browser saved files are opened outside Pictureshow; web in-app offline browsing is OFF-14 later scope. |
| OFF-05 | Native offline media includes selected audio, chosen subtitles and required playlist/init/segment resources. | Two selected languages and Off behavior survive airplane mode. Original embedded tracks can remain; external captions/artwork are saved separately with origin metadata. Offline HLS never follows a server URL or uses an incomplete rolling playlist. Local decoder/seek uses full-media timeline; switching to an undownloaded track offers reconnect, retaining playback. |
| OFF-06 | Native transfer policy is explicit and budgeted. | Pass requires OFF-06a through OFF-06e individually; no hidden eviction of pinned downloads. |
| OFF-06a | Network policy has a deliberate override. | Default to Wi-Fi-only; a per-job cellular override is explicit. Losing permitted network changes state to Waiting without publishing Ready. |
| OFF-06b | Budget is bounded by measured capacity. | Default account cap is min(10 GiB, 20% of reported storage quota); keep 512 MiB free when capacity is measurable. Unknown capacity requires a viewer-selected cap and checks at each chunk commit. |
| OFF-06c | Concurrency is bounded. | Run at most two transfers per account; pending jobs remain queued. Cap reduction pauses jobs before the next chunk can exceed the new cap. |
| OFF-06d | Byte accounting is exact. | Used bytes + remaining reservations + incoming unreserved bytes cannot exceed cap. Committing bytes reduces remaining reservation by the same count; disk-full pauses without losing completed assets. |
| OFF-06e | Cleanup respects explicit pins. | Never silently evict an explicit download. Auto-clean watched defaults off and previews exact titles/bytes before enabling; deleting owned partials does not delete an unrelated viewer's data. |
| OFF-07 | Native offline progress is a durable outbox, partitioned by server/viewer/item and local viewing sequence. | Store base server UserData, latest local position, explicit played/unplayed intent and observed completion, without replaying historical Start/Stop online. Reconnect authenticates same viewer and refetches current data before writes. If dirty fields still equal the base, update those fields only. Replaying the same desired value does not increment PlayCount. |
| OFF-08 | Concurrent progress changes use server-wins reconciliation at launch. | When a dirty server field differs from its stored base, retain the server value and a private local conflict record, and show that server progress was kept. No launch override chooser or maximum-position/wall-clock merge. Read back accepted writes before acknowledgment; ambiguous/crashed writes reconcile before retry. No compare-and-swap guarantee: another writer after the read can still win. |
| OFF-09 | Download ownership and removal protect household privacy. | Sign-out/account removal stops readers/jobs, deletes that viewer's private media/metadata and revokes its download-set sessions under CTRL-11. Failed byte cleanup is marked pending and hidden from other viewers; OS file protection plus deletion is sufficient, with no new per-account crypto layer. Local removal does not wait for online logout. Revalidated revocation blocks new transfers and app access; offline revocation cannot be enforced until reconnect. Browser-exported files remain viewer-controlled and cannot be recalled/deleted by sign-out. |
| OFF-10 | Native offline assets use app-private OS-protected storage and dedicated download-set tokens. | Use OS file protection, exclude downloaded assets from backup, and delete on removal; no periodic online license or invented media expiry. Use a dedicated device/session token per download set rather than the interactive account token, revoking at sign-out/removal under CTRL-11. Inspect Apple packages for retained source URLs/tokens in 84B: if retained, disclose the package contains a revocable bearer token and its exposure while valid. Redact own logs/exports under CTRL-10; do not promise token-free package contents without observed proof. |
| OFF-11 | Native offline video and music use the normal player and queue. | Same pause/seek/completion/tracks rules; music continues under MUS-04. Removing the current download first stops playback with confirmation. Network return never replaces a playing local file midway; switching quality/source is deliberate. Cast does not silently expose a phone file server; server-backed cast requires receiver access or an explained unavailable route. |
| OFF-12 | Corruption, eviction and stale assets recover honestly. | Verify length plus local content hash after transfer; compare server source/version/ETag when available. App upgrade reconciles files/manifest/outbox atomically. Missing files or OS-evicted assets become Missing with Redownload, never Ready. Delete only Pictureshow-owned records/files, with per-title and bulk confirmations starting on Cancel. |
| OFF-13 | Web launch offers Download file for original media. | Gate GET /Items/{itemId}/Download by EnableContentDownloading and item access, save the original without conversion, and label the browser-controlled file action. For container selections list individual originals and require deliberate saves rather than claiming an atomic offline bundle. Never claim saved files appear in an in-app offline library. Verify byte-identical file, denied permission, cancel and interrupted transfer in each supported browser. |
| OFF-14 | Later improvement, outside launch: web in-app offline library. | A separate implementation/qualification leg must cover offline shell, account-bound metadata, quota/eviction and local playback using Blob URLs for progressive files or a custom local HLS loader; no range-serving service worker. If adopted, support pre-Safari-26 writes with worker createSyncAccessHandle or explicitly raise supported floor; [createWritable compatibility](https://github.com/mdn/browser-compat-data/blob/main/api/FileSystemFileHandle.json) requires Safari 26. Until implemented label this row Later, never Verified launch parity. |

## Platform-dependent rows

| ID | Platform-dependent mechanism/limit | Acceptance and fallback |
|---|---|---|
| OFF-PD01 | Android TV/Google TV/Fire OS and Android touch: Media3 DownloadManager/DownloadService with dedicated non-LRU cache, private manifest and foreground transfer notification; original progressive files use a file transfer. [Android guide](https://developer.android.com/media/media3/exoplayer/downloading-media). | D-pad download management and storage warnings on TV. Fire needs no GMS. Scheduler/data/battery restrictions show Waiting. For converted HLS, sequential fetch must complete with zero unexpected transcode restarts; do not enable a parallel segment executor that fails that test. Verify force-stop, reboot, permissions and low storage on devices. |
| OFF-PD02 | iOS/iPadOS: background URLSession for original files; AVAssetDownloadURLSession for qualified finite HLS with selected media. [Apple offline APIs](https://developer.apple.com/documentation/avfoundation/offline-playback-and-storage). | Preserve opaque Apple asset locations and storage policies; do not move package internals. App force-quit can stop OS work; restore task/manifest on relaunch. Exclude assets from backup and measure offline completeness, including selected tracks. |
| OFF-PD03 | Apple TV: AVAssetDownloadURLSession is not available for tvOS; local media cache is purgeable. [Apple API](https://developer.apple.com/documentation/avfoundation/avassetdownloadurlsession), [tvOS storage model](https://developer.apple.com/library/archive/documentation/General/Conceptual/AppleTV_PG/). | No promise of durable travel downloads on Apple TV. Show “Offline downloads aren't supported on this device” and the supported phone/tablet route; any temporary cache is labeled and never marked a durable download. This is a documented platform exception, not a passed OFF-01 transfer. |
| OFF-PD04 | Web launch downloads save original files through the browser under OFF-13; no in-app offline library, offline app shell or range-serving service worker at launch. [WebKit storage policy](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/). | Browser/download-manager controls completion and file location. Explain that browser closure can interrupt transfer and saved files remain outside sign-out cleanup. Later OFF-14 must disclose Safari's seven-day script-writable-storage cap after Safari use without interaction on the site (Home Screen apps excepted), quota/eviction and platform write APIs; that cap does not delete an original file saved to the viewer's filesystem. |

## Planned vectors and proof

`offline-job` (all state transitions, duplicate callbacks, death/restart, canceled late success); `offline-budget` (exact bytes, reservations, unknown totals, concurrent final chunks, cap change); `offline-resume` (206/200/416, ETag change, truncated/corrupt resource); `offline-manifest` (atomic ready, tracks, eviction, schema upgrade); `offline-outbox` (base equals/differs with server-wins/private conflict record, dedicated download-set token lifecycle, explicit unplayed, repeated write, unknown acknowledgment, cross-account denial).

Native proof requires airplane-mode cold start and full decode/seek/end from local media. Test Original first, then finite converted video/audio with two track choices, interruption/range resume, low storage, removed account and server-wins reconnect conflict on isolated 10.10.7, 10.11.11 and 12.4; household 12.0.0 remains unchanged acceptance server. In 84B measure zero unexpected transcode restarts for sequential fetch and compare framework fetch patterns (Apple controls its own); inspect Apple packages for retained auth. Conversion stays a launch blocker. Web proves permitted original-file save, denied save, completion/cancel/interruption and external-file privacy. tvOS records OFF-PD03, not a transfer pass.
