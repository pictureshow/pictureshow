# Downloads and offline (launch draft)

**Status: required launch scope, not implemented or verified here.** Apply [shared rules](shared.md), [queue/ownership rules](session-control.md) and [exact API/version boundaries](launch-api.md). Sources inspected 2026-11-03: [Plex Downloads](https://support.plex.tv/articles/downloads-overview/) describes permission-controlled personal-media downloads and original/lower quality on supported apps; [Jellyfin Android download behavior](https://github.com/jellyfin/jellyfin-android/tree/master/app/src/main/java/org/jellyfin/mobile/downloads) is behavioral evidence only. No GPL implementation is incorporated.

| ID | Behavior | Acceptance criteria |
|---|---|---|
| OFF-01 | Download movie/episode/album/track/playlist or selected season episodes for travel, with a preview of scope, quality and storage. | Check viewer download/playback permissions and actual item access. Expand a container into a stable paged snapshot with entry deduplication for storage, preserving playback order. Show queued item count and best-known size; unknown size is explicitly estimated. No unsupported live/infinite stream is offered as a finite download. |
| OFF-02 | Download quality is Original, Compatible video (up to 720p/4 Mbps or 1080p/8 Mbps), or Compatible audio (128/256 kbps), subject to proven server/output support. | Download is not streaming negotiation alone. Original requires local codec/track support or an explicit warning before transfer. A finite, independently playable converted asset must pass offline checks before a compatible preset is enabled. No usable conversion means an honest unavailable preset plus supported original; conversion remains a launch qualification blocker for convertible fixtures. No server-side offline job/DRM is invented. |
| OFF-03 | Download states are queued, waiting for Wi-Fi/storage, preparing, transferring, verifying, ready, paused, failed, missing and deleting. | Only verified complete media plus manifest/metadata becomes Ready atomically. Percent uses known total only. Pause/restart survives process death; cancel/delete clears partials. Resume ranges only with a matching resource validator and 206 Content-Range; a 200 or changed version restarts safely. Concurrent attempts cannot exceed the storage reservation. |
| OFF-04 | Downloads screen works without a reachable server and groups ready/active/failed media, with Retry, Pause, Delete and storage settings. | Airplane-mode cold start opens a cached account's downloads without failing online token validation first. Artwork/title/episode/track labels and available subtitle/audio selections are cached. No catalog/search/page navigation implies an uncached full library is available offline. Unavailable items explain why; no infinite spinner. |
| OFF-05 | Local media includes selected audio, chosen subtitles and required playlist/init/segment resources. | Two selected languages and Off behavior survive airplane mode. Original embedded tracks can remain; external captions/artwork are saved separately with origin metadata. Offline HLS never follows a server URL or uses an incomplete rolling playlist. Local decoder/seek uses full-media timeline; switching to an undownloaded track offers reconnect, retaining playback. |
| OFF-06 | Wi-Fi-only is default, with explicit per-job cellular override and visible reservation/budget. | Default account budget is min(10 GiB, 20% of reported storage quota), reserve 512 MiB free where measurable, two simultaneous transfers maximum. Unknown free capacity requires a viewer-chosen cap and incremental checks. Used bytes + remaining reserved bytes + unreserved incoming bytes cannot exceed the cap; committing bytes reduces the remaining reservation; storage exhaustion pauses safely. Pinned explicit downloads are never silently evicted by Pictureshow; auto-clean watched is opt-in and previews exact scope. |
| OFF-07 | Offline progress is a durable outbox, partitioned by server/viewer/item and local viewing sequence. | Store base server UserData, latest local position, explicit played/unplayed intent and observed completion, without replaying historical Start/Stop online. Reconnect authenticates same viewer and refetches current data before writes. If dirty fields still equal the base, update those fields only. Replaying the same desired value does not increment PlayCount. |
| OFF-08 | Concurrent progress changes have a visible conflict outcome. | When a dirty server field differs from its base, retain the server value by default, keep local resume as a selectable alternative and offer Use this device once. Do not merge by maximum position or untrusted wall-clock time. Read back accepted mutation before outbox acknowledgment. Crash/unknown write reconciles value before retry. No compare-and-swap guarantee is claimed; another writer racing after the read can still win. |
| OFF-09 | Download ownership and removal protect household privacy. | Account/server removal or sign-out explains its local download cleanup scope, stops readers/jobs, destroys local access keys and makes that viewer's cached titles unavailable to other viewers. Successful removal does not depend on a network logout. Online revocation/disabled downloading blocks new transfers and further app access after revalidation. Offline revocation cannot be enforced before reconnect; explain this in privacy settings. |
| OFF-10 | Offline files use app-private storage, excluded from cloud/device backups where platform permits. | Native at-rest protection uses OS file protection/keystore facilities; web origin storage is not an OS user vault and is disclosed as such. Credentials stay out of saved media URLs, manifests and diagnostics. Logout deletes bytes or cryptographically revokes app access immediately, then retries failed byte cleanup with visible status. No mandatory periodic online license check or invented expiry for personal media. |
| OFF-11 | Offline video and music use the normal player and queue. | Same pause/seek/completion/tracks rules; music continues under MUS-04. Removing the current download first stops playback with confirmation. Network return never replaces a playing local file midway; switching quality/source is deliberate. Cast does not silently expose a phone file server; server-backed cast requires receiver access or an explained unavailable route. |
| OFF-12 | Corruption, eviction and stale assets recover honestly. | Verify length plus local content hash after transfer; compare server source/version/ETag when available. App upgrade reconciles files/manifest/outbox atomically. Missing files or OS-evicted assets become Missing with Redownload, never Ready. Delete only Pictureshow-owned records/files, with per-title and bulk confirmations starting on Cancel. |

## Platform-dependent rows

| ID | Platform-dependent mechanism/limit | Acceptance and fallback |
|---|---|---|
| OFF-PD01 | Android TV/Google TV/Fire OS and Android touch: Media3 DownloadManager/DownloadService with dedicated non-LRU download cache, storage manifest and native foreground transfer notification; progressive file path where appropriate. [Android download guide](https://developer.android.com/media/media3/exoplayer/downloading-media). | TV download management uses D-pad and storage-specific warnings; Fire OS needs no GMS for downloads. OS scheduler/data/battery restrictions can defer transfers; display waiting instead of false running. Verify file permissions, force-stop, reboot and low storage on real devices. |
| OFF-PD02 | iOS/iPadOS: background URLSession for original files; AVAssetDownloadURLSession for qualified finite HLS with selected media. [Apple offline APIs](https://developer.apple.com/documentation/avfoundation/offline-playback-and-storage). | Preserve opaque Apple asset locations and storage policies; do not move package internals. App force-quit can stop OS work; restore task/manifest on relaunch. Exclude assets from backup and measure offline completeness, including selected tracks. |
| OFF-PD03 | Apple TV: AVAssetDownloadURLSession is not available for tvOS; local media cache is purgeable. [Apple API](https://developer.apple.com/documentation/avfoundation/avassetdownloadurlsession), [tvOS storage model](https://developer.apple.com/library/archive/documentation/General/Conceptual/AppleTV_PG/). | No promise of durable travel downloads on Apple TV. Show “Offline downloads aren't supported on this device” and the supported phone/tablet route; any temporary cache is labeled and never marked a durable download. This is a documented platform exception, not a passed OFF-01 transfer. |
| OFF-PD04 | Web: secure-context service worker caches app shell and serves authenticated, account-bound local ranges; IndexedDB metadata, OPFS streaming writes where available, chunked Cache Storage fallback. [OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system), [quota/eviction](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria). | Query quota/persistence, request persistence from a deliberate action, handle QuotaExceededError and partial eviction. Browser origin/profile changes, clear-site-data, private mode and OS purging can remove downloads. Unsupported storage/decoder gets precise unavailability plus a supported browser/native route. No guaranteed background download after tab closure, no service worker used as an audio player. |

## Planned vectors and proof

`offline-job` (all state transitions, duplicate callbacks, death/restart, canceled late success); `offline-budget` (exact bytes, reservations, unknown totals, concurrent final chunks, cap change); `offline-resume` (206/200/416, ETag change, truncated/corrupt resource); `offline-manifest` (atomic ready, tracks, eviction, schema upgrade); `offline-outbox` (base equals/differs, explicit unplayed, repeated write, unknown acknowledgment, cross-account denial).

Proof requires airplane-mode cold start and full decode/seek/end from local media, not a request mock. Test original and converted video plus audio, two audio/subtitle choices, interruption/resume, low disk, removed account and reconnect conflict on both 10.10 and 12. Browser offline shell/range service and native OS transfers need integration tests in addition to vectors. tvOS records OFF-PD03 rather than an invented transfer pass.
