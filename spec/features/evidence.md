# Acceptance provenance and reference deviations

The parity requirements were derived from source/tests at the pinned commits and the project's projector acceptance corpus, inspected 2026-10-31. This file summarizes product behavior learned from that corpus without shipping private server, account, device-address or filesystem details. A historical PASS belongs to its recorded build/device/input; it is not a claim that this spec run repeated that test.

## Known deviations and evidence limits at this baseline

1. **First-error focus gap remains:** rc21 acceptance explicitly records roughly 0.5 s with no visible focus on ordinary Movie first error, reader OFF. CAT-11 describes intended usable recovery, not a claim that the first-error transition is perfect. Retry→fresh handoff was fixed separately; do not conflate it with first-error arrival.
2. **Returning action row can require scroll:** the fourth unselected returning action may be partially below the viewport until selected. Selected action/ring and full label must be brought into view; don't remove Play from start merely because a still did not show it.
3. **Latest Retry physical coverage is incomplete:** rc21's accepted native API30 reader-OFF R1 and R5b trials proved 30.007 s/30.014 s Retry budgets and fresh-read-while-report-held behavior. Reader-ON, guarded Select on unavailable primary, Series/Season natural-end cases and actual projector counterparts were not run in that acceptance. These remain required verification cases, not implied passes.
4. **Reader outline lag is distinct from missing input selection:** supplemental fresh-handoff evidence had three encoded frames (about 280–440 ms) of reader outline trailing input selection. Earlier first-error reader transfer showed longer uncertain lag. No frame-perfect screen-reader/input simultaneity claim is made. Compare adjacent frames and real focus events on the target platform.
5. **Input sent is not input delivered:** projector keyboard/HID sent-time, Android delivery, video timestamps and accessibility focus have separate clocks. A query can pause/restart the Android reader. A still after settlement or “OK sent” does not prove no intermediate focus loss or exactly one playback.
6. **Resource/codec evidence is device-specific:** emulator software codec order does not establish vendor hardware release. Up to two completed idle playback threads are intentional; PGS parser/end and framework window-insets/release warnings are separate known paths. Missing warnings on a release build are not proof of leak freedom. A timeout/bound event is an overlap risk, not normal sequential decoder evidence.
7. **Server/device content failures stay findings:** broken/truncated source runtime, an unsupported codec/output, a transient encoder/decoder error or unproved watchdog reboot cannot be turned into a passing parity expectation. Record selected source/method/output and actual first frames/progress/end separately. Preserve readable error/Back/recovery behavior.
8. **Phone detail freshness is an explicit integration gap:** see TOUCH-14 follow-on note. The touch branch contains later presentation additions and earlier playback/detail logic; use main's corrected semantic baseline when reconciling.
9. **Server preference audit correction:** audio language is honored through server default audio indices. A direct field-read search cannot disprove server-mediated selection/memory/subtitle policy. The settings matrix names both the consumed default-index behavior and missing local configuration controls/policies.

10. **DirectStream uses the static file URL in the reference:** the core reports `DirectStream` when that support flag wins, but opens `/Videos/{id}/stream?static=true`. This is not evidence of an actual server remux. The vectors preserve the source behavior; a port must identify the real negotiated/output path honestly. A future correction needs its own vector and platform review.

## Minimum port verification matrix

For each platform run: cold/warm start and restoration; one password and one Quick Connect login (where server enabled); two-account switch/sign-out/removal; library/search/person Back restoration; Movie/Series/Season details with default and large text; screen reader OFF and ON; plain keyboard/D-pad and touch where applicable. Exercise working, slow, failed, retried and abandoned reads/writes. Include pending request before/after deadline, held Select across publication, duplicate input and fresh data arriving before final reporting.

Playback needs actual direct, remux/copy-audio and full-transcode paths appropriate to real platform capabilities, text/external/bitmap-or-burned-in captions, paused/playing track switches and seeks, startup/rebuffer recovery, ordinary Stop/Back, credits/manual next, canceled next, physical end and season boundary. Verify server watch/resume/next state and encoding cleanup. A platform that cannot perform a path reports the reason and tests its honest fallback; it must not mark a fake local capability as parity.
