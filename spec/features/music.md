# Music library, queue and background audio (launch draft)

**Status: required launch scope, not implemented or verified here.** Uses [queue/control](session-control.md), [offline](offline.md), [API contract](launch-api.md) and APP accessibility rules. Evidence: [Jellyfin music organization](https://jellyfin.org/docs/general/server/media/music/) supports tagged music and multi-disc albums; [Plex music overview](https://support.plex.tv/articles/205744257-getting-started-with-plex-music/) documents a music library and multi-disc support. The Plex statement uses its official indexed excerpt; direct article retrieval was blocked. This draft covers general client music intent, not a claim of Plexamp-specific DSP/cloud-service parity.

| ID | Behavior | Acceptance criteria |
|---|---|---|
| MUS-01 | Music libraries offer albums, album artists, artists, songs, genres, playlists, favorites and search. | Page/filter/sort by stable identity without gaps/duplicates or cross-library leakage; preserve browse state on Back. Album artist and contributing artist remain distinct. Empty, inaccessible and failed library are distinguishable. Add music groups to global search without regressing video group order; label media types. |
| MUS-02 | Album/artist/playlist detail shows artwork, metadata and ordered tracks, with Play, Shuffle, Play next, Add to queue, Favorite and Download where supported. | Disc then track ordering uses tags, with stable name/ID fallback for missing/duplicate numbers. Various Artists compilations do not split the album incorrectly. Unavailable tracks are readable; playing a selected track starts that entry and retains the selected context. No “playable” container with no tracks. |
| MUS-03 | Mini-player and full Now playing expose title/artist/album, art, elapsed/duration, transport, seek, repeat/shuffle, destination and editable queue. | Same entry IDs/order on each surface. Live/internet audio has no invented duration. Queue changes and Stop are visible/announced without per-second chatter. TV queue has reachable move/remove actions as alternatives to drag; phone has native gestures plus accessible actions. |
| MUS-04 | Explicit audio-only playback continues when browsing, screen locks or app backgrounds. | This intentionally specializes APP-08/PLAY-24 for music only. User Stop, sign-out, queue clear or revocation ends audio. Interruption/audio-focus loss pauses or ducks per OS; resume only if OS permits and viewer did not pause meanwhile. Headphone disconnect pauses; reconnect does not unexpectedly blast speakers. Video does not acquire this exception automatically. |
| MUS-05 | OS media/lock-screen controls reflect current music queue. | Publish title/artist/art/duration/position and available actions; hardware headset Play/Pause/Next/Previous/Seek act once through reducer. Lock screen initial metadata appears with the first track and updates at transition. Stop removes stale control metadata; no other viewer sees cached previous-account art. |
| MUS-06 | Playback negotiates actual audio formats, quality and output route. | Original/lossless where supported; streaming quality Auto/original, 128/256 kbps capped conversion when required/selected. No claim of lossless through a lossy Bluetooth/Cast path. Audio-only conversion does not encode video. Recovery retains queue, position and pause intent and reports meaningful source/output facts. |
| MUS-07 | Consecutive compatible tracks play gaplessly where decoder/container supports it. | No app-inserted silence, overlap or duplicate EOS. Use a generated continuous split waveform and measured captured output to establish the gap. Lossy encoder delay, incompatible sample rates, server transcodes and remote routes get measured qualification; explain unavailable gapless rather than promising sample accuracy on every route. A crossfade is not a substitute for gapless. |
| MUS-08 | Queue obeys QUE-01..08 and restores as paused after process death. | Repeat One/All/Off, shuffle history, previous threshold, skipped failures and repeated tracks are deterministic. Selecting another album explains replacement when useful, never overwrites remote queue silently. Audio completion does not run video episode-next logic. Per-track reports belong to one renderer and never double count on OS/UI duplicate end events. |
| MUS-09 | Playlists can be created, renamed, played, appended, reordered and edited when server permits. | Persistent server entry IDs distinguish duplicate songs. Playback queue changes do not mutate a saved playlist without explicit action. Read back successful edits and expose denied/failed/unknown results; do not retry append after ambiguous success without reconciliation. Restriction/ownership prevents edits rather than hiding failures. |
| MUS-10 | Downloaded music uses the same manifest, budget and progress outbox as video. | Album/playlist snapshot order remains available offline; cached tracks need no server token check to start while disconnected. Online-only tracks in a mixed queue explain missing availability; one bounded skip per traversal, then stop. Reconnect does not replace local audio mid-track. |
| MUS-11 | Music works on TV as well as touch/web. | TV album/queue lists, now-playing artwork, reader order and screensaver behavior remain usable by remote at 1.3 text scale. Background audio does not keep video controls/decoder allocated. Music-to-video transition stops audio once before starting video, preserving saved queue for deliberate return. |

## Platform-dependent rows

| ID | Mechanism/limit | Acceptance and fallback |
|---|---|---|
| MUS-PD01 | Android/Fire: ExoPlayer playlist in Media3 MediaSessionService, foreground mediaPlayback service/notification, audio focus and becoming-noisy handling. [Android background audio](https://developer.android.com/media/media3/session/background-playback). | Foreground-service declarations/start policy and notification behavior are tested on supported OS versions and Fire hardware. Activity disappearance does not release intentional music. System kill can end playback; restore paused with clear state. |
| MUS-PD02 | iOS/iPadOS/tvOS: AVQueuePlayer or qualified native gapless engine, playback AVAudioSession, background audio mode, MPNowPlayingInfoCenter and MPRemoteCommandCenter (or supported successor with equivalent behavior). [Apple remote commands](https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter). | Observe interruption/route changes and release observers once. Real lock-screen/Control Center/headset/AirPlay tests required on iPhone; tvOS system Now Playing/Siri Remote replaces a nonexistent TV lock screen. No MusicKit subscription or Apple Music account needed for Jellyfin music. |
| MUS-PD03 | Web: persistent audio element, preloaded next track where appropriate and navigator.mediaSession, using feature detection. [Media Session API](https://developer.mozilla.org/en-US/docs/Web/API/Media_Session_API). | Browser/OS controls and background execution vary. Handle autoplay rejection with a visible Tap Play action; browser suspension/closure can stop audio and is not a guaranteed background service. A service worker does not play music. Gapless unsupported by the active engine gets explicit qualified status and measured transition behavior. |

## Planned vectors and proof

`music-catalog`: multi-disc/compilation/missing tags, artist versus album artist, paged search and permissions; `music-session`: interruption/noisy/duck/resume intent, lock command deduplication, music→video transition; `music-reports`: one viewing per track, restored paused queue, repeated same track entries, offline replay; queue suites from session-control. Playback continuity needs device audio capture and reference waveform; unit tests prove ordering, not audible gaplessness. Offline, Cast, remote and group music each reuse the same queue acceptance.
