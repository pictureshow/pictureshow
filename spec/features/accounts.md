# Discovery, sign-in and accounts

Sources: `MainActivity.kt` (servers/accounts/login/quick routes, `RemoteField`, `QuickConnectCode`, `SignInCompletion`), `ScreenModels.kt`, `DiscoveryFocus.kt`, `RemoteFieldNavigation.kt`, `AccountDevices.kt`, `Persistence.kt`; core `AccountStore.kt`, `JellyfinClient.kt` and auth/discovery models. See the actual core paths in the vectors' source metadata. Tests: `SignInAccountsTest`, `SignInSpeechTest`, `QuickConnectNavigationTest`, `QuickConnectRestoreTest`, `DiscoveryProgressTest`, `AccountRemovalTest`, `AccountRemovalWatchTest`, `DeviceAccountsTest`, `DeviceUpgradeTest`.

| ID | Screen/action and behavior | Acceptance criteria |
|---|---|---|
| AUTH-01 | Server page offers remembered servers, Server address, Connect, discovered LAN servers, scan status, Search again and Remembered accounts. Manual server URLs support reverse-proxy paths. | First use starts on address; a last server gives its remembered sign-in priority. Valid manual/discovered address verifies server then opens sign-in. Bad address/network/server errors remain actionable. Connect is disabled while connecting; rescan cannot duplicate an active scan. |
| AUTH-02 | Discovery changes from looking to discovered/complete or no-servers/manual-entry explanation. | A late first server does not steal focus while editing or connecting. It can become the useful initial target only when appropriate. LAN discovery failure leaves manual entry usable. Platforms unable to broadcast provide manual connection and an honest explanation. |
| AUTH-03 | Server address/Username/Password have one accessible label, native keyboard entry and Done behavior. Password is obscured. | Remote Down/Up leaves the editing field exactly once; held keys do not cascade through several destinations. Username Done advances toward password; Password Done signs in. Recreation retains appropriate input while leaving the flow cancels work/clears credentials. |
| AUTH-04 | Login loads public users and Quick Connect availability, accepts username/password, shows Signing in and friendly error. Picking a public user prefills username. | Wrong credentials leave form usable; retry with correct credentials works. No duplicate request while busy. Session-ended notice appears for rejected saved tokens, not ordinary sign-out. Back returns to chooser/discovery even if login was restored as root. |
| AUTH-05 | Quick Connect gets a code, polls approval, renews expired codes, and offers retry/disabled explanations and Back. | Code spoken digit by digit once when newly available and when renewed; visible code agrees with the approved code. Do not reannounce an unchanged code on Back/return, recreation or process restoration. Renewed status distinguishes invalid old code. Approval signs in once. |
| AUTH-06 | Quick Connect attempt belongs to its parent sign-in entry. | Back to password and reopening preserves still-valid code and polling attempt; HOME/process restore preserves the short-lived attempt. Leaving the sign-in flow cancels polling and clears the owner. Disabled Quick Connect offers username/password recovery, not endless renewal. |
| AUTH-07 | Saved-account chooser lists each viewer/server, Remove per account, sign in another user per server, Remove server and Add a server. | Current account selection is deterministic; a saved expired current viewer opens prefilled login. Same-viewer selection still refreshes Home. An error saving selection is visible and leaves the original account usable. |
| AUTH-08 | Remove account/server confirmation explains exact scope and starts on Cancel. | Full question is spoken once from Cancel; destructive action is not initially selected. Cancel/Back restore exact Remove opener. During persistence both controls and Back are guarded. Persistence failure leaves recoverable confirmation; success cannot reopen an old confirmation after re-adding the same viewer. |
| AUTH-09 | Remove account forgets that viewer; Remove server forgets its saved viewers; other servers/accounts remain. | Local commit works offline; best-effort remote logout cannot undo successful local removal. Active playback/launcher/history/selected-account references are reconciled. Removing a server identifies its affected account count. |
| AUTH-10 | Home Sign out immediately commits local sign-out, removes the active token while keeping its remembered server. | One activation reaches account/sign-in choice and does not erase other viewers; busy state prevents repeat activation. Network logout failure does not re-sign the viewer in. Session-ended copy is absent after voluntary sign-out. |
| AUTH-11 | Account-scoped Jellyfin device IDs isolate session progress, logout and ActiveEncodings. Legacy shared IDs migrate opportunistically using existing authorization. | Two saved viewers have distinct device IDs; deleting/logging out one cannot invalidate the other. Startup migration soft budget is 3 s; failed/disabled Quick Connect retains working old credentials and retries after 30 minutes. Report calls use the viewing account's device identity. |
| AUTH-12 | Unauthorized server responses expire only the matching credential; transient offline errors retain it. | Revoking one token presents reauthentication with same server/username; replacing it once returns Home. A stale unauthorized response cannot expire a newer token. Offline browse/verification error does not silently sign out or delete saved accounts. |

Touch adaptations are specified in [touch.md](touch.md): password Show/Hide, Material forms, dialog dismissal and compact navigation. They retain these account semantics.
