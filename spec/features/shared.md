# Shared application, input and recovery contract

Sources: `MainActivity.kt`, `Accessibility.kt`, `ConfirmationFocus.kt`, `RemoteFieldNavigation.kt`, `SearchEntry.kt`, `CatalogFocusHandoff.kt`, `PlaybackEntry.kt`, `WatchNext.kt`, `WatchNextRuntime.kt`. Regression sources: `HomeInitialFocusTest`, `HomeSettingsAndBackTest`, `ConfirmationInputFocusTest`, `ConfirmationAcknowledgementTest`, `PlaybackEntryRoutingTest`, `WatchNextTest`, accessibility test families in `app/src/test/`.

| ID | Behavior | Acceptance criteria |
|---|---|---|
| APP-01 | Startup reads saved accounts before choosing servers, chooser, login or current Home. Loading and storage-failure/Retry states are explicit. | Cold start and recreation preserve account identity; unreadable storage offers Retry rather than discarding sign-ins. No transient signed-out controls can act on a loaded current viewer. |
| APP-02 | Signing in, including the same viewer, completes to a fresh usable Home and removes the sign-in route from Back history. | Password, public-user-assisted password, Quick Connect, expired-token replacement and selecting the current saved account each land on Home; Back cannot reveal credentials/code pages. |
| APP-03 | TV D-pad/keyboard traversal exposes visible focus and brings the focused target fully into view. | UP/DOWN/LEFT/RIGHT and center/Enter/numpad Enter work at default and 1.3 text scale. Selected text, scaled pill, border and screen-reader ring fit without clipping or covering neighbors. Restore opener identity and scroll on Back, including after recreation/process restoration. |
| APP-04 | Screen readers get headings, useful action names, selected/toggle/current states and logical order. Decorative art is silent. | Cards and fields speak once; no duplicate caption/label, state, forced badge or hidden player surface. Static metadata is reachable. No automatic focus reset after the viewer deliberately moves to text or another action. Test reader ON separately from plain D-pad. |
| APP-05 | Status/errors are readable and announced without stealing unrelated focus or shifting a published header. | Loading/saving/expired/failure states are distinguishable. Dynamic clocks/countdowns do not chatter every tick. A real Retry or exit is reachable; late results cannot navigate or mutate a departed screen. |
| APP-06 | Back closes the nearest modal/IME/panel before leaving its owning page. Forms, confirmation and player have explicit special cases in their manifests. | Repeated Back unwinds predictably. A held key or old key-up cannot activate the fresh page. Native platform Back/Escape/menu gestures provide the same semantic exits. |
| APP-07 | Local account/settings persistence survives process death and an in-place signed upgrade. | No reset of selected account, remembered server, bitrate/passthrough/caption/segment choices or resume cards after upgrade. Activity recreation cannot duplicate a sign-in or playback session. |
| APP-08 | Backgrounding local video pauses; returning restores the same viewing's state and surface. Intentional background music follows [MUS-04](music.md), and remote-controller backgrounding follows [CTRL-06](session-control.md). | HOME/foreground or layout recreation does not produce duplicate Start/Stop, lose pause intent, leave black video or create an extra viewing. Process death may end the old viewing; new resume uses persisted server progress. A change of system font size or bold text during playback keeps the viewing and the controls take the new size. |
| APP-09 | External playback entry validates an item ID and nonnegative bounded position, resolves against the current account, and builds an item/detail/player Back stack. | Valid launcher Continue watching opens the intended item/position; unavailable or malformed entries explain failure and recover safely. Never trust a serialized stale item or a different account's route. |
| APP-10 | Android TV Watch Next publishes eligible Movie/Episode resume/next rows for the active viewer; deduplicates, honors launcher dismissal and removes obsolete/account rows. | Switching/removing/signing out cannot expose another viewer's rows. Dismissed rows stay dismissed. Provider IDs hash account identity; intents/artwork contain no access token. No equivalent OS integration is claimed where unavailable. |

Platform-dependent behavior: preserve semantic state and safe recovery while using the platform's native focus, screen reader, safe area, keyboard, lifecycle and media-session facilities. Report unavailable integration (LAN discovery, launcher Watch Next, billing, codecs) honestly; it does not justify a dead control. Reduced motion and larger text use native accessibility preferences; TV focus enlargement is suppressed for accessibility where the Android implementation does so.
