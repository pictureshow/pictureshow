# Phone/tablet additions and adaptations

Source branch `phone` at the pinned commit in [README](README.md). Sources: `InterfaceMode.kt`, `TouchApp.kt`, `TouchNavigation.kt`, `TouchTheme.kt`, `TouchAccountScreens.kt`, `TouchCatalogScreens.kt`, `TouchSearchScreen.kt`, `TouchSettingsScreens.kt`, `TouchPlayer.kt`, `TouchPlayerContent.kt`, `TouchPlayerSheets.kt`, `PlayerPlaybackHost.kt`; core `CatalogModels.kt` adds people metadata. Tests on that branch: `InterfaceModeTest`, `TouchNavigationTest`, `TouchFormsTest`, `TouchCatalogScreensTest`, `TouchContinuationTest`, `TouchPlaybackHostTest`, `TouchPlayerControlsTest`, `TouchPeopleDetailsTest`.

| ID | Addition/adaptation | Acceptance criteria |
|---|---|---|
| TOUCH-01 | Android television UI mode chooses TV; other devices choose touch shell. | Android phone/tablet never needs a D-pad to complete a flow; TV retains remote behavior. Native Apple/web chooses appropriate device/input adaptation with equivalent features. |
| TOUCH-02 | Home/Libraries/Search/Settings navigation uses bottom bar below 600 dp and navigation rail at/above 600 dp. Player and sign-in hide chrome; IME hides navigation while visible. | Rotate/resize tablet and phone without duplicate destinations or loss of selection. Reselect current root is no-op; switching roots saves/restores root state and Back stack. Insets applied once; content is not obscured by keyboard/cutout/nav bar. |
| TOUCH-03 | Touch pages scroll above IME; width caps at 720 dp; under 480 dp height uses compact title/back/spacing. Minimum common actions 48 dp high. | Landscape with keyboard, large text and small window keeps form submit, Back, dialog choices and errors reachable. Portrait/landscape/split view retain input and screen. |
| TOUCH-04 | Server/manual connection, login, Quick Connect and accounts use Material forms/actions; password Show/Hide; account removal native confirmation dialog. | Server URL keyboard/no unintended autocorrection; Username Next and Password Done; Show/Hide retains password/selection and accessible label. Back/dismiss cancels removal unless committing. Account identity/expiry semantics match accounts manifest. |
| TOUCH-05 | Dedicated Libraries tab shows every library in a vertical grid of cards, with no sideways scrolling, under one “Libraries” heading; Home shows content shelves with responsive touch cards/grid. | Every library/title is tappable, collection drill-down and paged sorting work, empty states expose Refresh. Responsive rows/cards avoid truncated interactive targets, and cards in a row share one height whatever their data. |
| TOUCH-06 | Library sort is a dropdown (Title, Date added, Release date) with separate ascending/descending action. | Active selection is stated; changing sort closes menu and resets results safely; Back/outside dismisses without changing value. |
| TOUCH-07 | Detail includes responsive hero/metadata/always-present actions with CAT-08..13 pending and Retry behaviour, season choice chips, people/cast/crew cards and person biography/filmography. Touch arranges the actions its own way: Play, with Play from start beside it when there is something to resume or a return is pending; Watched and Favorite; and one Play on TV control whose menu holds Play on TV, Play next on TV, Add to TV queue and Play on TV from start. Every action stays reachable. On a series page Next up, Seasons and Episodes come before the cast. | Credit person ID routes to Person irrespective of credit kind (Actor/Director/etc.); role/name announced once; biography readable, filmography opens and returns correctly. People metadata absent does not leave empty/dead controls. Once a Play is accepted it shows a check and its requested wording, and every other Play is disabled under its plain name. |
| TOUCH-08 | Search uses labeled touch field, Clear, IME Search, recent chips and clear-history action; grouped results and helpful empty/minimum-input copy. | Query/results/history semantics match CAT-14..16. Keyboard dismissal and tab switching preserve intended query. Retry uses current query, not earlier typed text. |
| TOUCH-09 | Settings is a list: value rows open radio choice dialogs, whole-row switches, and navigation rows for accounts, troubleshooting, support and about. | Includes the Conversion notice switch and “This phone” or “This tablet” (shared report, capture and share). Same defaults/effective values as SET-01..11. Long radio choices scroll (including short landscape with “Scroll for more options”); Cancel/Back/outside dismisses. Selection saves immediately once; checked state is announced. |
| TOUCH-10 | Fullscreen touch player has tap-to-show/hide controls, Play/Pause, ±10 s, scrubber, Audio/Subtitles/Chapters/Speed/Playback info sheets, explicit Stop and, on a phone, a Portrait/Landscape toggle. Same playback owner as TV, so PLAY rows hold on touch through one implementation. | Video fills behind cutouts, controls use safe insets. Scrub preview updates without seeking each drag; commit seeks once, clamped; missing duration is safe. A phone opens the player landscape and has the toggle. A large screen (a window whose smallest width is 600 dp or more, which is every iPad at full screen) requests no orientation and has no toggle: the device's rotation decides, and the player fills the screen either way. Leaving the player restores what was requested before it; a window crossing that size mid-play changes rule without restarting anything. Orientation changes and background/foreground preserve current viewing, tracks, subtitle delay, position and pause intent. In a window 600 dp or wider, controls take one line only when transport, options and Stop all fit at their natural size, font scale included; otherwise transport and Stop on one line and the options below it, starting at Pause's edge, on one line unless a very large font needs another. |
| TOUCH-11 | Touch controls state saves selected sheet/visibility/seek interaction for UI lifetime; idle auto-hide uses the shared 10 s policy (PLAY-04). Back closes sheet, then controls, then exits. | Paused/reader/sheet/scrub states pin controls as implemented; no stray click on underlying video. Stop exits immediately through report/cleanup. Loading/error overlay offers meaningful Back to details. |
| TOUCH-12 | Audio/Subtitles/Chapters/Speed/Playback info are modal bottom sheets with selected radio state where there is a choice, and Done. Chapter rows carry their images when the server has them and open at the current chapter. Subtitle delay Earlier/Reset/Later and burned-in explanation present. Speed and Playback info hold the same content as PLAY-25 and PLAY-26. | Track/chapter pick applies once then dismisses; Done/Back/outside dismisses with no change. Off is a genuine choice (both audio and subtitles). Delay respects bounds and burned-in disablement. All choices remain reachable in short landscape. Below 480 dp height Speed is one segmented row showing every rate; elsewhere it is a radio list opening at the current rate. |
| TOUCH-13 | Skip and next-episode cards are touch buttons; next card Play now/Cancel; screen-reader mode requires manual Play now and the card announces itself. After a return from the background a pending next waits for Play with no countdown. Returning to the foreground paused shows the controls. The card shows a number only while its countdown is running, and that number is real time at the current speed (vector `next-countdown`). Skip and the next card share one anchor at the top end of the player, in every state; while the card is up, Skip sits inside it, after Cancel, so Cancel never moves. On a window too narrow for the conversion notice beside them they sit below it, and stay there when the notice ends until nothing is showing. | Same segment/continuation/completion semantics as PLAY-15..19. No auto-advance while paused/buffering/scrubbing; countdown and physical end each start next once. Captions rise only above the controls panel; the top anchor leaves them alone. |
| TOUCH-14 | Touch About/license/support screens expose same information; license text selectable, active supporter code selectable. | Native text/reading order, store unavailable/fallback and Back behavior remain usable. Platform naming does not claim TV-specific capability on a phone. |

Touch detail follows CAT-08..13 in touch form: the published page and action grid stay through a playback return, status sits in an overlay with no layout footprint, a tap during the wait is captured with its desired value and runs once in order on fresh data, the 30-second bound is explained, Back abandons, Retry works while loading with a new budget per deliberate Retry, read and write failures stay separate, and a polite live region carries the pending and “Ready.” cues. Touch and TV share one playback owner, so HLS, release and report fixes reach both modes.
