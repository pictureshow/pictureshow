# Casting and output routes (launch draft)

**Status: required launch scope, not implemented or device-qualified here.** Use [shared controls/queue](session-control.md), [API reference](launch-api.md) and APP/PLAY acceptance. Evidence: [Jellyfin web Cast configuration](https://jellyfin.org/docs/general/clients/web-config/) documents Google resources; [Plex controller/receiver support](https://support.plex.tv/articles/203082707-supported-plex-companion-apps/) documents sender/receiver intent with client-version caveats. Pictureshow improves destination clarity, privacy, handoff recovery and truthful report ownership.

| ID | Behavior | Acceptance criteria |
|---|---|---|
| CAST-01 | Play on chooser distinguishes This device, Jellyfin sessions, Google Cast and native AirPlay routes. | Device name, transport, active title/viewer if authorized and connection state are readable. Discovery does not autoplay. No-target, denied permission, unavailable SDK, unreachable server and unsupported media have different recovery. Same-named devices remain distinguishable without exposing network addresses. |
| CAST-02 | Chromecast supports start/resume, pause/play, seek, Stop, volume/mute where supported, track selection and queue continuation. | Receiver negotiates against its actual formats/decoder, not the phone's profile. Server direct/remux/transcode route, current title and position are observable. External text captions/artwork/segments have receiver-reachable URLs and correct CORS/auth. Track change retains pause/position; queue entries retain identity. Real receiver playback is required for acceptance. |
| CAST-03 | Sender-to-receiver transfer preserves viewer-selected title/position/queue. | Follow CTRL-03. Pause local output before remote starts; on failure expose Resume here. On successful transfer, receiver is sole report owner and tracks progress with its account-specific device identity. Sender reconnect displays receiver's live state, not an old local clock. |
| CAST-04 | Disconnect, Stop casting and Play here have distinct meanings. | Disconnect detaches controls while receiver continues; Stop casting stops receiver and its reporting/resources; Play here requests stop and returns at observed position with original pause intent. Unconfirmed remote stop never silently starts a second audible output. UI remains usable if sender was killed or receiver disappears. |
| CAST-05 | Receiver can reach media independently. | Receiver fetches each manifest/segment/subtitle/artwork through a configured reachable base. Sender-only VPN, loopback forward, self-signed certificate, blocked HTTP/mixed content, CORS or local-network permission produces a specific explanation. No automatic public exposure, cloud relay or third-party CORS proxy. A server address working on the phone proves nothing about receiver access. |
| CAST-06 | Receiver authenticates as the intended Jellyfin viewer. | Preferred custom receiver uses its own Quick Connect session authorized by sender; no admin key or password is sent over Cast. Disabled Quick Connect has an explicit supported receiver sign-in/Play on Jellyfin-session alternative. Broad bearer-token forwarding is not silently enabled as a fallback; receiver credentials/URLs stay out of telemetry, history and queue snapshots. |
| CAST-07 | AirPlay uses native media routing and retains the originating viewing. | Route chooser opens on explicit action, label reflects actual external playback and disconnect restores deliberate intent. Seek/tracks/subtitles and music lock controls are tested with an actual receiver. Do not create a second Jellyfin session/report stream solely for AirPlay output. Screen mirroring alone is not evidence of remote media playback. |
| CAST-08 | Cast works for music and recorded video; Live TV uses its real live window. | Music queue, metadata, repeat/shuffle survive sender recreation. Live tune/Stop closes owned live resources; unknown duration is Live, not zero-length VOD. Cast of private local downloads is unavailable unless a separately qualified route truly carries them; no hidden LAN file server. |
| CAST-09 | Third-party SDK loading and discovery are viewer-controlled. | Explain Google Cast before enabling its web loader; disabled mode makes no Google SDK requests. Local network refusal keeps local playback and Jellyfin session remote usable where server access exists. Revoke/disable ends discovery and stops reconnect attempts; it does not silently stop active remote media. |
| CAST-10 | Custom receiver and native TV target are separately qualified. | A free Default Media Receiver experiment may prove device/media reachability only. It is not launch proof for authentication, independent reporting, queue editing or SyncPlay. A configured custom receiver ID cannot inherit another project's receiver/application registration. Report app registration/hosting requirements separately from SDK code. |
| CAST-11 | Every platform can use authorized Jellyfin sessions even when an OS casting protocol is unavailable. | Do not substitute screen mirroring or OS D-pad control for the server session protocol. For unsupported Cast/AirPlay sender roles, chooser explains the native-platform alternative; record the exact PD row in the release matrix. No omission is called an implemented sender. |

## Platform-dependent rows

| ID | Platform-dependent mechanism/limit | Acceptance and fallback |
|---|---|---|
| CAST-PD01 | Android touch: Google Cast sender/MediaRouter and Media3 Cast integration in GMS-capable builds. [Android sender](https://developers.google.com/cast/docs/android_sender). | Real Google Play Services/discovery required; fake SDK transport tests do not prove Cast. Fire OS/no-GMS variants retain Jellyfin session control and clearly lack Google Cast sender discovery. Android TV is a native Jellyfin target; Cast Connect is separate registered integration. |
| CAST-PD02 | iPhone/iPad: Google Cast iOS SDK plus native AVRoutePickerView/AVPlayer AirPlay. [Cast setup](https://developers.google.com/cast/docs/ios_sender), [route picker](https://developer.apple.com/documentation/avkit/avroutepickerview). | Add actual Bonjour/local-network declarations and permission recovery. Pin SDK availability from the chosen release (Google's page currently has conflicting minimum-iOS summaries); compile/deployment check decides. No Cast SDK tvOS sender is invented. |
| CAST-PD03 | Apple TV: native Jellyfin target; OS AirPlay receiver is managed by system. Android/Fire have no native Apple AirPlay sender API in this plan. | Apple TV does not implement a custom AirPlay server; test system route availability. Android/Fire offer Jellyfin target control or Cast where supported, and an explicit AirPlay-unavailable explanation. No private/reverse-engineered AirPlay dependency. |
| CAST-PD04 | Web: Cast CAF sender on supported browsers/HTTPS; Remote Playback API when exposed; Safari native AirPlay controls with feature-detected picker. [Cast web](https://developers.google.com/cast/docs/web_sender), [Remote Playback](https://developer.mozilla.org/en-US/docs/Web/API/Remote_Playback_API). | Remote Playback is not universal and does not guarantee Chromecast. Cast web is unavailable on iOS Chrome per Google docs. Browser prompt needs user gesture; permission/SDK failure is recoverable. Safari's native AirPlay is a route, not CAF. Firefox retains Jellyfin session targets if native remote playback is absent. |
| CAST-PD05 | Receiver hardware, network and DRM/codec capabilities differ. [Cast media support](https://developers.google.com/cast/docs/media). | No universal HDR, Dolby, precise seek or sample-accurate sync promise. A feature unsupported by this actual receiver gets server conversion or an honest explanation. Record projector manufacturer support separately from live discovery/first-frame evidence. |

## Planned vectors and proof

`cast-handoff` (all owner states, local pause before remote output, receiver READY/failed/load timeout, unknown Stop, sender death/reattach); `cast-capability` (GMS absent, browser unsupported, unavailable track/volume, live window); `cast-auth` (viewer mismatch, server base-prefix, canceled/revoked Quick Connect, receiver-only auth, token redaction); `cast-queue` (repeat/shuffle/duplicate entry transfer). Device test: compatible original, audio-only remux, full transcode, captions, music queue, receiver shutdown, sender lock/death and VPN-only server failure. Default receiver tests never substitute for custom receiver qualification.
