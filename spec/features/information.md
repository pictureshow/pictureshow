# Diagnostics, About, licenses and Supporter

Sources: `ThisTvScreen.kt`, `ThisTvReport.kt`, `DeviceCapabilityProbe.kt`, `VideoCodecProbe.kt`, `PictureshowTheme.kt`, `AboutScreens.kt`, `Supporter.kt`, `PlaySupporterBilling.kt`, `SupporterScreen.kt`, `app/src/main/res/values/strings.xml`, generated license assets. Tests: `ThisTvReportTest`, `DiagnosticMemoryAndSpeechTest`, `DiagnosticTextChunksTest`, `AboutLicensesTest`, `SupporterTest`, `PlaySupporterBillingTest`.

| ID | Feature/behavior | Acceptance criteria |
|---|---|---|
| INFO-01 | This TV reads current video/audio/display profile and shows technical capability summary, Refresh, View/Hide device profile JSON and Back. | Refresh is initial useful focus; error explains Refresh recovery. List names deduplicate aliases, numbers are human-readable (no huge decimal FPS strings), unreported profile/level is said honestly. Refresh after route change shows new actual sink. |
| INFO-02 | Long device report/JSON is lazily rendered in readable word-boundary chunks; toggling JSON preserves useful focus/scroll. | D-pad/reader can read every block at font 1.3 without cutting words, clipping or huge graphics-memory spikes. No one giant texture/paragraph that kills the reader. Back returns to This TV opener in Settings. |
| INFO-03 | About displays Pictureshow, version name/code, MPL-2.0, Legitimate LLC, source and privacy URLs, licenses and Back. | Accurate current build version, readable URLs/attribution, first actionable focus on Open-source licenses; Up reads preceding copy. Back restores About opener. Touch adds product tagline. |
| INFO-04 | License list displays dependency count, library name/version/id/license and opens complete notices. | All bundled license texts are reachable. Back restores the precise selected library, including far down the lazy list. Wide rows do not scale beyond clip. |
| INFO-05 | License detail offers full text as word-boundary focusable chunks and Back. | Up/Down reads all text in order, no missing boundary words, large text still fits; Back returns list not Settings. Touch uses selectable full text. |
| INFO-06 | Supporter screen explains free/open-source product and monthly support prioritizes feature-request consideration, without guaranteed delivery. | Description, no-guarantee line, localized price and monthly renewal/cancellation terms are visible and readable in order before purchase. Free app playback remains available independent of subscription. |
| INFO-07 | Billing states: Checking Google Play, available offer/Become a supporter, pending payment, active supporter/code, unavailable reason. | Only usable store offer exposes purchase; pending is not active. Store cancellation/error returns coherent state. Active state displays/copies or makes readable the supplied supporter code, request email instructions, and Manage/cancel. Missing code says to reopen later rather than inventing one. |
| INFO-08 | Unavailable billing keeps the support explanation and focused reason, with Back; account/network/product/general failures have specific copy. | No dead subscription button, substitute external payment route or unearned entitlement. If manage intent cannot open, show native-store instructions. Reader reaches full price/renewal/reason; Back is immediate. |

Platform-dependent: “This TV” becomes a suitably named real device/browser capability report; unavailable APIs are marked unreported, never synthesized as Android values. Purchase is available only through the platform's actually configured supported billing path. At this snapshot only Google Play Supporter billing is implemented. Apple/web ports must explicitly show support purchase as unavailable until their own authorized implementation exists; they cannot claim billing parity or invent a subscription price/provider. Use the platform's real store/localized price and cancellation instructions when implemented. Source/privacy/LLC attribution remain common; dependency notices reflect each platform's actual licensed dependencies.
