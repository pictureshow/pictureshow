# Seerr requests (launch draft)

**Status: the Android reference implements it on TV and phone; Apple, desktop and web owe the port and the `seerr` suite (`spec/vectors/seerr.json`).** Seerr (formerly Jellyseerr/Overseerr) is the household's own request server. Pictureshow is a Seerr client only: it never talks to Radarr/Sonarr or TMDB's API, and it never hosts anything. Shapes and answers below were checked against a running Seerr v3.5.2 linked to Jellyfin 12.

| ID | Behavior | Acceptance criteria |
|---|---|---|
| SEERR-01 | Each Pictureshow account connects its own Seerr, from Settings. | Settings shows "Requests (Seerr)" with the connected Seerr user or "Not connected". Connecting asks for the address and either the viewer's Jellyfin name and password (default) or a Seerr API key. The address is normalized (`seerr/url`): a bare host gets `https://`, a default port, trailing slash or `/api/v1` suffix is dropped; credentials, query, fragment, other schemes and spaces are refused before any call. Nothing is saved until Seerr confirms who the viewer is (`/auth/me`). Disconnect removes only this account's connection. |
| SEERR-02 | Secrets stay on the device and with their account. | The session cookie, the Jellyfin password kept for renewal, and an API key are stored encrypted with a device-held key and bound to the Pictureshow account; the address and Seerr user are the only plaintext. Signing out or forgetting the Jellyfin account drops its Seerr connection in the same write, and a sign-in that finishes after sign-out is not saved. Seerr calls use a dedicated HTTP client with redirects off: the Jellyfin token never goes to Seerr and Seerr's cookie or key never goes anywhere else. Diagnostics never print a secret. |
| SEERR-03 | Jellyfin sign-in mode renews a lapsed session once. | Seerr answers a missing session 401 and a stale one 403, the same 403 as a missing permission, so a 401/403 is checked against `/auth/me` before renewing with the saved password, and a missing permission is never mistaken for an ended session. A renewal is saved only while the connection still exists. A changed Jellyfin password reads as "sign in to Seerr again", not as a wrong password now. |
| SEERR-04 | An API key only ever acts as the viewer's own Seerr user. | A Seerr API key alone acts as Seerr's admin (user 1); `X-API-User` selects the user. Connecting looks the viewer up by Jellyfin user id across every page of Seerr users (`seerr/link`); that lookup is the only call without `X-API-User`. No match fails closed: "Your Jellyfin account isn't linked in Seerr", nothing is saved, and no Request button appears. Every later call names the linked user (`seerr/headers`); a config with no linked user can't call Seerr at all. There is no fallback to the admin or anyone else. |
| SEERR-05 | Requests: Trending, Search and My requests. | TV: Home's header shows "Requests" while the account is connected. Phone: a Requests tab appears in the bar while connected. Trending and Search show Seerr's movies and series (people dropped) as the app's own poster cards with a year · Movie/Series line and the Seerr status; posters come from TMDB's image host with no server credentials, and a card without a poster shows the placeholder, never server art. Search is debounced and the words are percent-encoded in full (`seerr/query`). My requests lists the viewer's own requests, newest first, with request status (`seerr/request-status`, `seerr/request-display`). |
| SEERR-06 | A title page requests a movie or chosen seasons. | Movie: Request when the title is unknown or deleted (`seerr/movie-requestable`). Series: a season picker lists seasons with episode counts; a season already available, processing, pending or requested by anyone (from `mediaInfo.requests[].seasons`, since `mediaInfo.seasons` stays empty after a request) is shown but can't be picked (`seerr/seasons`). Specials (season 0) are left out. Request sends nothing until a season is picked (disabled on phone; on TV it stays focusable and does nothing). A 202 "No seasons available to request" is a failure, never a request. Errors say what happened (`seerr/error`): permission, quota, blocklisted, already requested, signed out of Seerr, not linked, unreachable. |
| SEERR-07 | Search shows what the library lacks. | While connected, the app's search adds a "Not in your library" row after the library rows: Seerr's results for the same words minus people, titles Seerr marks available, and titles the library search found with the same normalized name and year (`seerr/offers`). The row is absent when nothing is left, when Seerr fails, or when the account isn't connected; the library's "No results" line still follows the library alone. Choosing a card opens SEERR-06. |

## Vectors and proof

`seerr`: `url`, `query`, `poster`, `media-status`, `request-status`, `request-display`, `can-request`, `movie-requestable`, `seasons`, `offers`, `error`, `headers`, `link`, `session-cookie`. Android runs them in `SeerrVectorsTest`; `SeerrClientTest` replays observed Seerr answers (renewal, 202, fail-closed API key); `SeerrStoreTest` covers encrypted per-account storage and sign-out retention.
