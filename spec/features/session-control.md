# Shared playback control and queue (launch draft)

**Status: required launch scope, not implemented or verified by this document.** Drafted 2026-11-03 against `de505e2`. Applies to Android TV/Google TV/Fire OS, Android phone/tablet, iPhone/iPad, Apple TV and web. Android defines the reference after implementation; this draft defines the intended new behavior. All [shared input, accessibility and recovery rules](shared.md) apply.

Protocol source: [versioned API contract](launch-api.md). These are original Pictureshow policies; Jellyfin session relay and SyncPlay are different transports. [Plex Companion](https://support.plex.tv/articles/203082707-supported-plex-companion-apps/) documents controller/receiver roles, with a warning excluding newer mobile apps. Direct Plex article retrieval was blocked; its official indexed excerpt and prior intent inventory support this statement. This supports the intent, not a claim that every current Plex client supports every role.

| ID | Behavior | Acceptance criteria |
|---|---|---|
| CTRL-01 | One playback owner, identified by server/viewer/device/session/viewing generation and target kind. | Local player, Jellyfin target, Cast receiver and AirPlay route are distinct. Only the rendering owner reports playback; a controller cannot create a second watched count. AirPlay remains the originating player's viewing. Late events from a replaced owner cannot change current playback or a different viewer. |
| CTRL-02 | Commands enter one serialized reducer with desired play state, item/queue entry, bounded ticks and current generation. | Pause twice stays paused; a held key does not toggle twice. Relative seeks accumulate against pending target per PLAY-07. Reject stale targets, invalid numbers, unsupported commands and wrong server/account. Native/system/remote input cannot bypass the reducer or its freshness guards. |
| CTRL-03 | Target handoff has selecting, connecting, preparing, active, disconnected, returning and failed states. | Retain the local queue/position while preparing. Pause local output before remote playback can become audible; commit new owner only after receiver readiness/position confirmation. Failure offers Resume here and retains intent. Returning here explicitly stops remote playback or explains an unconfirmed stop before local Play; no automatic double playback on network loss. |
| CTRL-04 | Commands expose sent, confirmed, rejected or unknown result. | HTTP 204 is dispatched, not Played. Require a matching observed state within 5 s for ordinary control; then show not confirmed and Refresh. No blind replay of PlayNow, toggle, relative seek or queue insertion after a timeout. A refreshed desired Pause may be sent deliberately. Delayed acknowledgment cannot confirm a newer command. |
| CTRL-05 | Session capabilities and authorization drive visible actions. | Never advertise unsupported media, track selection, volume, seek, queue edit or navigation. Server denial removes stale control rights. Remote target inherits its own signed-in viewer's permissions; no controller token is forwarded to a TV. Same-server item IDs cannot address another server. |
| CTRL-06 | Route/report ownership survives backgrounding and reconnect. | Controller backgrounding does not stop its receiver. Local video retains PLAY-24 pause policy. Explicit audio playback follows MUS-04. Reconnect obtains current target state before enabling mutations; old queued commands expire rather than replay. Stop/release only this viewing's encoding/live stream. |
| CTRL-07 | Control modes compose without competing clocks. | In SyncPlay, an attached TV's transport commands become group requests, not independent local pause/seek. AirPlay output can remain in a group only when measured clock control meets SYN-05. Cast receiver must itself be a qualified group participant; otherwise explain the limitation and offer local playback or explicit Leave group before casting. Never claim sync for an unmeasured output. |
| CTRL-08 | Now playing is reachable throughout browsing, with target name, title, state and Stop/disconnect actions. | Mini-player opens full controls without creating playback. Disconnect controller leaves remote output running with explicit copy; Stop ends it. Start another local title while remote output runs requires a deliberate destination choice. Back restores opener/scroll; permission/loading/error changes retain readable status and focus. |
| CTRL-09 | Credentials, discovery and diagnostic data have explicit ownership. | Discover on viewer request; no continuous LAN scans or third-party Cast web script before enablement. Logs/export contain fixed outcome categories, relative times and synthetic/session-local IDs, never media URLs, auth, server filesystem paths or private device addresses. Permission refusal has a usable alternative. |
| QUE-01 | A queue holds ordered entry IDs, media IDs, current entry, history, repeat, shuffle permutation and revision. | Two copies of the same track are distinct entries. Use exact signed 64-bit ticks; web serializes ticks beyond safe Number range as decimal strings at its adapter boundary. Changing account partitions saved queues; no credentials in a queue. |
| QUE-02 | Play now replaces queue with the selected ordered context; Play next inserts the selected block immediately after current; Add to queue appends. | Preserve block order and intentional duplicates. Repeated distinct Play next operations are last-in-first-next; one operation replayed in the same local command generation is deduplicated. If no current entry, insert at zero and remain stopped until deliberate Play. Server dispatch with uncertain result is not automatically retried. |
| QUE-03 | Remove/move/clear use entry identity and a revision. | Moving before current preserves audible item/clock. Removing current selects its successor at the removed index, otherwise previous final entry; preserve playing/paused intent. Removing last stops. Clear upcoming keeps current/history; Clear all stops. A stale revision refreshes before a viewer repeats an edit. |
| QUE-04 | Repeat Off/One/All and deterministic shuffle preserve context. | Natural end repeats current only for One, wraps only for All. Explicit Next ignores One; at final entry Off/One stops, All wraps. Previous at position >3 s restarts current, otherwise selects history/previous; first Off/One restarts, All wraps. Shuffle keeps current, permutes upcoming with an explicit stored permutation, and preserves visited history. Disable shuffle restores canonical upcoming order excluding already visited entries. |
| QUE-05 | Playback errors do not create infinite skipping. | Automatic music continuation can skip each unavailable upcoming entry once per traversal, stating failure; stop when exhausted, even with Repeat All. Video failure never silently starts a different title. Explicit Retry is separate from auto-advance. End/next/remote callbacks consume one completion generation. |
| QUE-06 | Persistent playlist and current playback queue are separate. | Editing a playback queue does not silently change the server playlist. Save/Create/Add/Remove/Move playlist operations show server permissions, preserve entry IDs and read back actual order. Pending/unknown mutations are reconciled before retry. |
| QUE-07 | Transfer preserves queue intent across local, remote and Cast owners. | Preserve current entry, position, repeat/shuffle and selected tracks only where target supports them. Missing target capability is explained before destructive replacement. A target's authoritative queue wins after attach; never overwrite it with a stale phone snapshot. |
| QUE-08 | Queue restoration is recoverable. | Restore per viewer after process death as paused, validate accessible items and download availability, and disclose removed/unavailable items. An offline saved queue never attempts network access. Persist before publishing a successful edit; failure retains last committed queue and offers retry. |

## Planned vectors

Add executable suites only with production reducers/adapters on all platforms; a placeholder JSON suite would break the existing fail-on-unknown runner. Required operations/cases:

- `session-owner`: target generations, viewer switch, stale response, duplicate report suppression, AirPlay owner retained, handoff prepare/fail/commit/return, unknown remote Stop.
- `session-command`: desired pause/unpause, ±seek accumulation, 64-bit ticks, malformed numbers, timeout/not-confirmed, denied rights, capability removal, no replay after reconnect.
- `queue-edit`: duplicate media IDs, PlayNext block and repeated blocks, append without current, remove/move current/earlier/last, clear upcoming/all, stale revision and persistence rollback.
- `queue-order`: explicit shuffle permutation (do not depend on platform PRNG), history, repeat at EOS versus explicit Next, Previous at 2.999/3.000/3.001 s, error traversal exhaustion, queue transfer and account partitioning.
- `playback-mode`: stopped video versus explicit background audio, remote-controller background, SyncPlay command routing and unsupported output.

Platform-dependent: controls use the native media-session/route APIs. A browser tab cannot promise to keep receiving commands after OS suspension or closure; a TV without a running client is not a wakeable target. Such states show unavailable/reconnect, never success.
