# Viewer home and library browsing

Android reference addition, 2026-11-10. This extends CAT-01/CAT-04 and the settings honor matrix. Kotlin core: `HomePreferences.kt`, `HomePreferencesStore.kt`; UI: `CatalogCustomization.kt`. Language-neutral cases: `spec/vectors/home-browse.json` (suite `home-browse`). A logic-vector pass does not qualify the UI, account persistence or server access controls.

| ID | Viewer behavior | Acceptance |
|---|---|---|
| HOME-01 | Customize home per viewer: show/hide rows, move a row up/down, restore defaults. | Stable row keys, duplicate ordering keys ignored, explicitly ordered rows first; new/unlisted rows keep source order. Empty rows stay omitted. Hiding Libraries never removes the separate Libraries landing route. Every row can be shown again in the editor. |
| HOME-02 | Pin a collection, playlist, favorites, genre or studio as a row. | Choices fetched as the signed-in viewer with bounded, searchable pages. Collections/playlists save only IDs; fresh authorized item reads resolve labels and fresh child queries resolve contents. Genre/studio pins save names; labels render on Home only with fresh nonempty results. No saved title or cached contents can resurrect a forbidden row. Favorites queries Movie/Series with `isFavorite=true`. Pins deduplicate by kind/value. Unpin also removes ordering/hidden entries for that key. |
| HOME-03 | Combine Continue watching and Next up. | Resume order first, then Next Up order. Deduplicate by item ID; if Resume contains an episode of a series, omit that series' Next Up episode. Combined key `watching` has its own hide/order state. Turning this off restores the two independent row keys and their saved choices. |
| HOME-04 | Remove/restore a series from Next Up. | Filter only Next Up by SeriesId. Resume, play history, episodes and detail playback selection remain intact. Persist `hiddenSeries` per viewer; editor restores individual currently returned series or all removed series. No played/favorite/progress mutation accompanies removal. |
| HOME-05 | Choose Home, Libraries or an accessible library as the landing view. | Apply once per fresh home destination, after preferences load. Back from a landing route reaches Home without redirecting again. Missing/inaccessible saved library falls back to Home; no cached label is shown. Changing the choice affects the next new Home session. |
| HOME-06 | Remember library Grid/List and sort/direction. | Per viewer and library ID; defaults Name/Ascending/Grid. TV and touch use a single column for List, with bounded landscape art. Preserve paging, exact opener restoration, column-preserving D-pad movement and font scaling in either mode. |
| HOME-07 | Save on Jellyfin when available, otherwise on this device. | `GET/POST /DisplayPreferences/usersettings?userId=<viewer>&client=pictureshow`; full `CustomPrefs["pictureshow.home.v1"]` JSON uses HomePreferences schema below. Preserve every unrelated DTO/custom field. Commit local pending state first; failed remote GET/POST never discards that choice. Pending local state wins over older server data until explicit Retry server save. Successful write clears pending. Surface storage errors; never claim a failed local commit succeeded. Account key is server ID + viewer ID. Sign out/forget server purges preferences and pending state. No token in preference payload. |
| HOME-08 | Respect existing server user display configuration. | Read signed-in user's Configuration. Honor `MyMediaExcludes` only for the Libraries home row, `LatestItemsExcludes` independently for latest rows and `HidePlayedInLatest` for latest items. Preserve server view order (including configured `OrderedViews`). This client stores its row customization in its own DisplayPreferences client namespace; it does not overwrite Jellyfin web's ten section slots. |
| BROWSE-01 | Filter by genre, year, official rating, unwatched, favorites, resolution and person, together with sort. | Different facets intersect. Each facet has one value; blank omits the parameter. Exact mapping: `genres`, `years`, `officialRatings`, `isPlayed=false`, `isFavorite=true`, `minWidth/maxWidth`, `personIds`. Genre/year/rating options come from user/library-scoped `/Items/Filters`; people from viewer-scoped `/Persons` with parentId. Clear resets all facets. Choice/read failure offers Retry without claiming no results. |
| BROWSE-02 | Resolution selects encoded video width. | Any omits both bounds; SD ≤719; HD 720–1919; Full HD 1920–3839; 4K and above ≥3840. Explicit labels describe width rather than assuming height/aspect ratio. No client-side filter of only the loaded page. |
| BROWSE-03 | A filter change replaces the result generation. | Cancel page/read jobs and queued grid moves; reset offset/items/total/end state; keep selected sort/direction. Every page carries all filters. Late/noncancellable previous pages cannot publish. Empty and failed pages preserve existing paging/retry contracts. Back from detail preserves current filters and opener. |
| ACCESS-01 | Server remains the authority for ratings, blocked tags and library permissions. | Rows, pin validation, pin contents, filter facets, named choices, searches, details and browse pages use current viewer token plus userId. No admin fallback, global metadata enumeration or unscoped ID hydration. On demo Jellyfin 12, explicit denied-parent metadata queries and `/Items/Latest` bypass parent permissions; use ordinary sorted `/Items` for latest and authorize a nonblank metadata parent through `GET /Items/<id>` before querying facets or named choices. The ID-batch projection alone is not an authorization check. HTTP denial is an error/unavailable result, not a license to show saved data. Account/session changes instantiate a new catalog session. Restricted-user device/server evidence is required in addition to transport tests. Client filtering does not implement or weaken server policy. |

HomePreferences v1: `order: string[]`, `hidden: string[]`, `pins: {kind: COLLECTION|PLAYLIST|FAVORITES|GENRE|STUDIO, value: string}[]`, `mergeWatching: boolean`, `hiddenSeries: string[]`, `landing: home|libraries|library:<id>`, `libraries: {<id>: {sortBy: string, descending: boolean, list: boolean}}`. Missing values use empty/false defaults, except landing=home and library sortBy=SortName. Unknown JSON fields are ignored on read; invalid JSON falls back to the local/default layout. Unsupported future schema migration requires a new CustomPrefs key.

The home builder is available from Home on TV and touch. Its full-screen scrolling editor and filter editor use native buttons, readable headings, 48 dp minimum controls and normal Back dismissal. TV safe margins are 48 dp horizontal / 32 dp vertical. Viewers can read current toggle values and selected facet values. Acceptance covers D-pad, TalkBack and font scales 1.0–1.3; screenshots alone cannot prove reader traversal.

API reference checked against the demo Jellyfin 12 OpenAPI on 2026-11-10 and [official Jellyfin SDK GetItems docs](https://kotlin-sdk.jellyfin.org/dokka/jellyfin-model/org.jellyfin.sdk.model.api.request/-get-items-request/index.html). Minimum-version qualification remains Jellyfin 10.10+.

Apple and desktop owe the complete implementation and these vectors. Web owes UI/storage/HTTP/device qualification even where its pure rules pass the vectors. Do not mark any platform accepted from this specification alone.
