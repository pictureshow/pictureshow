# Viewer home and library browsing

Android reference addition, 2026-11-10. This extends CAT-01/CAT-04 and the settings honor matrix. Kotlin core: `HomePreferences.kt`, `HomePreferencesStore.kt`; UI: `CatalogCustomization.kt`. Language-neutral cases: `spec/vectors/home-browse.json` (suite `home-browse`, 87 cases including editor projection/reorder, filter presentation and HTTP authority guards). Android executes the cases through HomeBrowseVectorsTest; native interaction assertions qualify controls separately. A logic-vector pass does not qualify the UI, account persistence or server access controls.

| ID | Viewer behavior | Acceptance |
|---|---|---|
| HOME-01 | Customize home per viewer: show/hide rows, reorder, restore defaults. | Stable row keys, duplicate ordering keys ignored, explicitly ordered rows first; new/unlisted rows keep source order. Empty rows stay omitted. Hiding Libraries never removes the separate Libraries landing route. Every row can be shown again in the editor. The editor projects only the active watching mode: combined shows `watching` and omits `resume`/`nextup`; separate does the reverse. Hidden rows stay editable. Reordering visible keys preserves dormant mode entries and their relative order in saved preferences; bounds and unknown keys are no-ops. |
| HOME-02 | Pin a collection, playlist, favorites, genre or studio as a row. | Choices fetched as the signed-in viewer with bounded, searchable pages. Collections/playlists save only IDs; fresh authorized item reads resolve labels and fresh child queries resolve contents. Genre/studio pins save names; labels render on Home only with fresh nonempty results. No saved title or cached contents can resurrect a forbidden row. Picker reads clear the old page and hide old selectable choices throughout a replacement query’s debounce/loading/error states; account/kind/library changes reset picker state. Late canceled reads cannot publish choices or errors. Favorites queries Movie/Series with `isFavorite=true`. Empty/unavailable saved pins use a generic kind label in the editor, so they can be removed without redisplaying saved metadata. Pins deduplicate by kind/value. Unpin also removes ordering/hidden entries for that key. |
| HOME-03 | Combine Continue watching and Next up. | Resume order first, then Next Up order. Deduplicate by item ID; if Resume contains an episode of a series, omit that series' Next Up episode. Combined key `watching` has its own hide/order state. Turning this off restores the two independent row keys and their saved choices. |
| HOME-04 | Remove/restore a series from Next Up. | Filter only Next Up by SeriesId. Resume, play history, episodes and detail playback selection remain intact. Persist `hiddenSeries` per viewer; editor restores individual currently returned series or all removed series. No played/favorite/progress mutation accompanies removal. |
| HOME-05 | Choose Home, Libraries or an accessible library as the landing view. | Apply once per account navigation session, after preferences load. Back and an explicit Home-tab choice reach Home without redirecting again; the Home tab consumes any pending landing. Preserve consumption across configuration/navigation restoration; a new account or cold app session can apply its landing. Missing/inaccessible saved library falls back to Home; no cached label is shown. Changing the choice affects the next cold app/account session. |
| HOME-06 | Remember library Grid/List and sort/direction. | Per viewer and library ID; defaults Name/Ascending/Grid. TV uses a single column with bounded landscape art. Touch uses compact rows with a 56 dp wide poster and title/year/runtime/rating metadata, approximately 100 dp minimum height. Preserve paging, exact opener restoration, column-preserving D-pad movement and font scaling in either mode. |
| HOME-07 | Save on Jellyfin when available, otherwise on this device. | `GET/POST /DisplayPreferences/usersettings?userId=<viewer>&client=pictureshow`; full `CustomPrefs["pictureshow.home.v1"]` JSON uses HomePreferences schema below. Preserve every unrelated DTO/custom field. Commit local pending state first; failed remote GET/POST never discards that choice. Pending local state wins over older server data until Retry after a failed sync. Successful write clears pending and removes the retry banner. Retry is shown only for a failed save or pending sync, never on an ordinary successful read or while saving. If caching a server read fails, retain the readable server layout and warn. If clearing the pending marker fails after an acknowledged write, retain the already committed local choice, warn and allow retry. Surface storage errors; never claim a failed local commit succeeded. The actual app service facade must forward preference reads/writes and facet/picker calls with the viewer’s device identity; qualify that facade as well as the HTTP client. Account key is server ID + viewer ID. Sign out/forget server purges preferences and pending state. No token in preference payload. |
| HOME-08 | Respect existing server user display configuration. | Read signed-in user's Configuration. Honor `MyMediaExcludes` only for the Libraries home row, `LatestItemsExcludes` independently for latest rows and `HidePlayedInLatest` for latest items. Request viewer-scoped `UserViews` with `includeHidden=true` to retain display-hidden libraries for the separate Libraries route and independent latest rows; this flag does not grant denied library access. Apply `MyMediaExcludes` only to the home shortcut row. Both TV and touch build the separate Libraries route from the fresh authorized library list, independently of customized home rows. Preserve server view order (including configured `OrderedViews`). This client stores its row customization in its own DisplayPreferences client namespace; it does not overwrite Jellyfin web's ten section slots. |
| BROWSE-01 | Filter by genre, year, official rating, unwatched, favorites, resolution and person, together with sort. | Different facets intersect. Each facet has one value; blank omits the parameter. Exact mapping: `genres`, `years`, `officialRatings`, `isPlayed=false`, `isFavorite=true`, `minWidth/maxWidth`, `personIds`. Genre/year/rating options come from user/library-scoped `/Items/Filters`; people from viewer-scoped `/Persons` with parentId. Clear resets all facets. Each nonblank facet counts once, including the resolution width range as one constraint; whitespace-only values are inactive. Removing a chip clears only that facet and preserves all others. Empty results with active filters say “No movies/shows/music/titles match these filters” using the library noun, with Clear filters initially focused on TV. The Filters chip displays the constraint count. Choice/read failure offers Retry without claiming no results. |
| BROWSE-02 | Resolution selects encoded video width. | Any omits both bounds; SD ≤719; HD 720–1919; Full HD 1920–3839; 4K and above ≥3840. Explicit labels describe width rather than assuming height/aspect ratio. No client-side filter of only the loaded page. |
| BROWSE-03 | A filter change replaces the result generation. | Cancel page/read jobs and queued grid moves; reset offset/items/total/end state; keep selected sort/direction. Every page carries all filters. Late/noncancellable previous pages cannot publish. Empty and failed pages preserve existing paging/retry contracts. Back from detail preserves current filters and opener. |
| ACCESS-01 | Server remains the authority for ratings, blocked tags and library permissions. | Rows, pin validation, pin contents, filter facets, named choices, searches, details and browse pages use current viewer token plus userId. No admin fallback, global metadata enumeration or unscoped ID hydration. On demo Jellyfin 12, explicit denied-parent metadata queries and `/Items/Latest` bypass parent permissions; use ordinary sorted `/Items` for latest and authorize a nonblank metadata parent through `GET /Items/<id>` before querying facets or named choices. The ID-batch projection alone is not an authorization check. HTTP denial is an error/unavailable result, not a license to show saved data. Account/session changes instantiate a new catalog session. Restricted-user device/server evidence is required in addition to transport tests. Client filtering does not implement or weaken server policy. Public image GET does not enforce viewer policy: demo12 returned a permitted Playlists library collage containing a denied movie poster. Render neutral artwork for aggregate container types CollectionFolder/UserView/Folder/BoxSet/Playlist/Genre/MusicGenre/Studio and any nonblank CollectionType, including inherited art fallbacks. Fresh authorized Movie/Series/Episode artwork is unchanged. Nineteen shared image cases live in network.json; Android and Web execute them. |

HomePreferences v1: `order: string[]`, `hidden: string[]`, `pins: {kind: COLLECTION|PLAYLIST|FAVORITES|GENRE|STUDIO, value: string}[]`, `mergeWatching: boolean`, `hiddenSeries: string[]`, `landing: home|libraries|library:<id>`, `libraries: {<id>: {sortBy: string, descending: boolean, list: boolean}}`. Missing values use empty/false defaults, except landing=home and library sortBy=SortName. Unknown JSON fields are ignored on read; invalid JSON falls back to the local/default layout. Unsupported future schema migration requires a new CustomPrefs key.

The home builder is available beside Search/Settings on TV and in the touch Home overflow. TV editors reuse the shared full-height settings side panel and native TV value/switch/list rows. Touch editors use a navigation-icon app bar and centered content capped at 640 dp. Both use separate section spacing, readable theme foreground for headings/status text, 48 dp minimum targets and normal Back dismissal; TV has no separate Back bar and initially focuses the first real control. Switches expose on/off state. Value rows open radio pickers with the current choice marked and visible/focused; year first selects a decade, then a year. A saved named choice outside the first page is resolved through a fresh viewer-authorized item read (or scoped name search for genre/studio); only successfully resolved metadata may be prepended, and pagination offsets still count page results only. People use a 40 dp circular headshot (initials fallback), name, available count and current-choice check. Search is debounced with IME Search and no separate Find button. Viewer-facing labels are written explicitly, with no usernames or server type identifiers.

Each editable home row has a leading visibility control and a visible Hidden label when hidden. A picked row shows explicit movement/drop guidance (TV: “Moving · Up/Down · OK to drop”; touch: “Moving · Release to drop”), including Hidden when applicable. Visibility and Unpin are unavailable until the row is dropped or the move is canceled. Disabled rows expose no mutating accessibility actions, including rows outside the active move and all rows while saving. Drop and cancellation restore the remaining rows’ controls and accessibility actions, with only movement directions valid at each row’s current position. TV OK picks up the reorder target, Up/Down move it with stable-key animation, OK commits the drop, and Back cancels an in-progress move before closing. Touch offers a drag handle plus accessibility Move up/Move down actions; pinned rows alone have an overflow Unpin command. Combined/Separate is one switch below the row list. Filter editors show compact summaries and retain one filled Apply action plus quieter Clear in a fixed footer. Library headers group the current sort/direction, selected Filters(count) and grid/list control; touch additionally shows independently removable filter chips. A failed save says “Couldn’t save to your server. Saved on this device.” only after the local commit succeeded. While writing, show “Saving layout…” and disable conflicting edits. Acceptance covers D-pad, TalkBack and font scales 1.0–1.3; screenshots alone cannot prove reader traversal.

API reference checked against the demo Jellyfin 12 OpenAPI on 2026-11-10 and [official Jellyfin SDK GetItems docs](https://kotlin-sdk.jellyfin.org/dokka/jellyfin-model/org.jellyfin.sdk.model.api.request/-get-items-request/index.html). Minimum-version qualification remains Jellyfin 10.10+.

Apple and desktop owe the complete implementation and these vectors. Web owes UI/storage/HTTP/device qualification even where its pure rules pass the vectors. Do not mark any platform accepted from this specification alone.

Home-row pin pickers use a check and “On your home” for an already pinned choice; this is distinct from a single-value filter radio picker. Unpin opens a command sheet titled with the fresh authorized row label (or its generic unavailable label), without a radio control. Next up switches explicitly say “Shown in Next up” or “Removed from Next up”. Offer bulk Restore all removed series only for multiple removed series or a removed series absent from the current list; one visible removed series is restored by its own switch. Restore default layout has a separate Layout section and confirmation panel, initially focusing Cancel on TV. Cancel and Back restore focus to the invoking reset row or pin overflow button and never alter preferences; confirmed restore preserves per-library display preferences.
