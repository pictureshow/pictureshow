# Subtitle download (SUB-DL, launch draft)

Find and download subtitles through the server's remote-subtitle API. Jellyfin answers `GET /Items/{id}/RemoteSearch/Subtitles/{language}` and `POST /Items/{id}/RemoteSearch/Subtitles/{subtitleId}`; a subtitle provider plugin (OpenSubtitles is the common one) does the searching. Both routes need the viewer's "Allow subtitle management" permission, or an administrator. Shared rules live in core `RemoteSubtitlePolicy`; `spec/vectors/subtitle-download.json` freezes them.

**SUB-DL-01 Where and whether.** Offered from the player's Subtitles chooser (including when it has nothing to pick) and from the title page of a movie, episode, video or music video ("Find subtitles"). Not offered for a downloaded copy, Live TV or a missing episode. Before any search the client reads `Users/Me` (Policy) and `Libraries/AvailableOptions` (`SubtitleFetchers`), which need no admin rights, and says why it can't search instead of showing an empty list: no permission ("Your account isn't allowed to download subtitles…", naming the admin setting) is checked before no provider ("Your server has no subtitle provider…", naming the OpenSubtitles plugin and where an admin installs it). An unreadable answer allows the search, whose own status then decides: 401/403 reads as not allowed, no answer as unreachable, anything else as failed with Try again.

**SUB-DL-02 Language.** The first search uses the viewer's server subtitle language, then audio language, then the device language, then English, each mapped through `Localization/Cultures` (two- or three-letter, and alternate three-letter codes such as `fra` to the culture's search code `fre`); a code the server doesn't know is skipped. The language list puts those preferred languages first, then widely used subtitle languages in this order (eng, spa, fre, ger, por, ita, dut, pol, rus, ara, chi, jpn, kor, tur, swe, heb, each mapped through the cultures the same way, so Jellyfin 12 lists French as `fra`; only those the server lists), then every other culture by display name, each once, so a remote reaches common languages without scrolling the whole list. Changing language starts a new search; no results says so and suggests another language.

**SUB-DL-03 Results.** Best first: a hash match (made for this exact file), then human over machine/AI translation, then downloads, then community rating; ties keep the provider's order; blank and duplicate ids are dropped. Each row shows the release name (or provider and format) and a line of facts in this order: made for this video, hearing impaired, forced, machine translated, format, provider, download count.

**SUB-DL-04 After download.** The server saves the file and refreshes the item asynchronously. The client polls the item (1 s, up to 30 s) until a new external subtitle stream appears. Jellyfin lists external files first and renumbers every stream, so the client maps the playing audio by identity (embedded streams by order within their type, external ones by codec, language, title and flags) and picks the new stream by the requested language, then format. In the player it reopens at the current position with the new subtitle and the mapped audio, and says "Added. Subtitles switched to {language}." On a title page it confirms the file is added and will be in Subtitles. If the stream never appears, say the server hasn't listed it yet and switch nothing; a failed download keeps the results.

Platforms owe: Android (done, leg 163). Desktop (done, leg 172): “Download subtitles…” at the end of the player's Subtitles menu opens a dialog on core `RemoteSubtitleSearch` with Android's wording; once the server lists the file the viewing reopens at the same place with it selected, speed and subtitle timing kept (`DesktopSubtitleDownload.kt`; desktop runs `SubtitleDownloadVectorsTest`). Desktop has no title-page “Find subtitles” yet. Apple and web: pending; the vectors register as pending until ported.
